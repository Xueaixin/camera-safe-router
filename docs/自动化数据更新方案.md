# 自动化数据更新方案

## 1. 目标和边界

下一阶段自动化分成两条独立流水线：

- 摄像头数据：建议每天更新，只重建摄像头和禁行边快照。
- OSM 路网：建议每月更新，从中国 PBF 切分京津冀并重建完整路网缓存。

两条流水线不能互相隐式触发，也不能直接覆盖正在使用的数据。任何校验失败都必须保留上一有效版本。

生产定时任务应由 Windows Task Scheduler、systemd timer、Kubernetes CronJob 或独立作业调度器执行。Codex 自动化可以辅助开发和提醒，但不应作为生产数据更新运行时。

## 2. 摄像头每日更新

### 2.1 来源

```text
POST https://www.jjz365.cn/CameraData/GetAllRing
Body: empty
```

上线前需要确认接口使用许可、认证方式、速率限制、可用性和字段变更通知。不得把第三方 Cookie、令牌或高德密钥写入源码。

### 2.2 建议频率

- 每天 `03:15 Asia/Shanghai` 执行一次。
- 失败后可在 30 分钟和 2 小时后各重试一次。
- 连续失败不影响现有路线服务，但必须告警。

频率由部署配置决定，不硬编码在业务逻辑中。

### 2.3 流水线

```text
远程下载到 downloads/*.part
  -> 保存原始响应及请求元数据
  -> JSON 结构和字段校验
  -> 统计源记录及字段分布
  -> 排除 IsSixRingOut 语义为 1，保留并统计缺失或非法值
  -> ID、坐标、数量变化和重复坐标校验
  -> 生成候选 cameras/map.json
  -> 构建候选禁行快照并检查匹配率
  -> 同盘原子替换当前 map.json
  -> 调用本机刷新 API
  -> 校验 readiness 和新版本
  -> 归档报告；失败则回滚
```

### 2.4 校验规则

至少检查：

- HTTP 成功、响应体非空且可解析为预期数组。
- 每条记录含有效 `Id/Lng/Lat`；统计 `IsSixRingOut` 的存在性、类型和值分布。
- 排除字符串或数值语义为 `1` 的记录；`0`、缺失和非法值均保留，后两类单独计数并告警。
- ID 不为空；同坐标不同 ID 不盲目去重。
- 经纬度在合理中国范围，转换后仍在路网候选范围。
- 总数相对上一版本的变化超过配置阈值时停止自动发布。
- 30 米匹配率或禁行边数显著下降时停止发布。
- 候选快照能够持久化，且至少一条固定零冲突路线仍通过。

建议把数量变化阈值、最小匹配率和允许的字段缺失数放入版本化配置，而不是散落在脚本中。

### 2.5 原子发布和回滚

- 下载、过滤和报告都写入 `downloads` 或 `work`。
- 候选文件与最终 `cameras/map.json` 必须位于同一文件系统，使用原子重命名发布。
- 发布前把当前文件复制到 `backups/cameras/<timestamp>-<hash>.json`。
- 后端刷新失败时恢复上一文件，并再次触发刷新或继续使用进程内旧快照。
- 后端自身仍应执行“只排除 `IsSixRingOut=1`”过滤，不能只信任更新脚本。

### 2.6 建议实现形态

首版可在后端仓库增加独立 Java CLI 模块或明确入口，复用 Jackson、坐标转换和快照构建代码，但不与 Web 服务的生命周期绑定。调度器只负责运行 CLI 和收集退出码。

不建议把远程下载直接塞进当前 `@Scheduled` Web 进程：这会把外部接口、磁盘发布、路由服务可用性和重试生命周期耦合在一起。

## 3. OSM 月度更新和京津冀切分

### 3.1 来源和命名

```text
中国：http://download.openstreetmap.fr/extracts/asia/china-latest.osm.pbf
北京：http://download.openstreetmap.fr/extracts/asia/china/beijing-latest.osm.pbf
```

当前使用 `beijing-latest.osm.pbf`。京津冀阶段下载中国源，切分结果发布为 `jingjinji-latest.osm.pbf`。

建议每月第一个周日 `02:00 Asia/Shanghai` 下载，避开摄像头日更窗口。下载和构图可能持续数小时，调度任务必须禁止重入。

### 3.2 多线程下载

服务器自动化建议使用 aria2，而不是自己维护分片 HTTP 实现：

```powershell
aria2c.exe `
  --continue=true `
  --max-connection-per-server=8 `
  --split=8 `
  --min-split-size=16M `
  --auto-file-renaming=false `
  --allow-overwrite=true `
  --dir="$routingDataRoot\downloads" `
  --out="china-latest.osm.pbf.part" `
  "http://download.openstreetmap.fr/extracts/asia/china-latest.osm.pbf"
```

如果数据源提供 HTTPS，应优先 HTTPS。仅有 HTTP 时不能依赖传输安全，必须结合文件结构检查、来源元数据、大小异常检测和本地哈希归档。

### 3.3 京津冀切分

首版建议采用带缓冲区的固定矩形和 `complete_ways`，避免城市行政边界把跨界道路截断。候选矩形：

```text
west=113.0, south=35.5, east=120.5, north=43.0
```

该范围覆盖北京、天津和河北并预留跨界道路缓冲，但仍是待 POC 验证的候选配置。正式启用前要记录北京、天津、河北边缘和跨省高速代表点，不应只凭矩形数值宣布覆盖完成。

示例命令：

```powershell
osmium extract `
  --bbox 113.0,35.5,120.5,43.0 `
  --strategy complete_ways `
  "$routingDataRoot\downloads\china-latest.osm.pbf.part" `
  --output "$routingDataRoot\work\jingjinji-candidate.osm.pbf" `
  --overwrite

osmium fileinfo --extended "$routingDataRoot\work\jingjinji-candidate.osm.pbf"
osmium check-refs "$routingDataRoot\work\jingjinji-candidate.osm.pbf"
```

如果后续要求严格行政区数据，可改用北京、天津、河北联合多边形，但路由产物仍建议在行政边界外保留道路缓冲区。

### 3.4 路网候选验证

切分完成后不能直接替换当前文件。必须在版本化候选目录中：

1. 记录源 URL、下载时间、Content-Length、源哈希、切分配置、产物哈希和 osmium 版本。
2. 导入 GraphHopper 新缓存，例如 `graph-cache/jingjinji-<hash12>`。
3. 记录节点、边、可驾车索引边、边界、峰值内存和导入耗时。
4. 重新生成摄像头匹配报告和禁行边快照。
5. 运行北京固定路线、北京边缘、北京到天津、北京到河北和跨城无路异常用例。
6. 确认缓存冷启动和只用缓存启动均通过。
7. 审核磁盘空间，至少同时保留当前版本、候选版本和下载临时文件。

### 3.5 发布方式

当前后端不支持运行中热换路网。推荐蓝绿数据目录：

```text
graph-cache\jingjinji-<old-hash>\
graph-cache\jingjinji-<new-hash>\
osm\archive\jingjinji-<date>-<hash>.osm.pbf
osm\jingjinji-latest.osm.pbf
```

验证通过后，在维护窗口更新 `ROUTING_PBF_PATH` 和 `ROUTING_GRAPH_CACHE_PATH`，重启服务，等待 readiness，再运行 HTTP 冒烟。失败时恢复旧环境变量和旧服务。

不要在已有缓存目录中覆盖 PBF。当前后端会检测哈希不一致并拒绝加载，这属于预期保护。

## 4. 版本清单和报告

每次自动任务建议生成一个 UTF-8 JSON 清单和一份中文 Markdown 报告，至少包含：

- 任务类型、开始/结束时间和退出状态。
- 数据源 URL、HTTP 元数据和工具版本。
- 输入、输出 SHA-256 和字节数。
- 过滤、切分和阈值配置版本。
- 摄像头源数、纳入数、排除数、匹配率和未匹配数。
- 路网节点、边、边界、缓存目录和图指纹。
- 执行过的测试及其真实结果。
- 发布版本、上一版本和回滚位置。

日志和报告不能包含 Cookie、令牌、密钥或完整用户定位。

## 5. 失败策略

| 失败点 | 行为 |
|---|---|
| 下载超时或中断 | 保留 `.part` 供续传，不影响 current |
| JSON/PBF 解析失败 | 隔离候选，不发布 |
| 记录数异常 | 停止并告警，等待人工审核 |
| 摄像头匹配率下降 | 停止并生成差异报告 |
| GraphHopper 构图失败 | 删除或隔离候选缓存，继续旧图 |
| 真实路线回归失败 | 禁止切换 |
| 新服务 readiness 失败 | 回滚旧路径和旧服务 |
| 报告或清单写入失败 | 视为任务失败，不发布 |

自动化的首要目标是可回滚和不污染当前版本，不是无条件追求“最新”。
