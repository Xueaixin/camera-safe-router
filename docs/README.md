## 文档更新规则

- API 字段、状态码或错误码变化时，先修改 `reference/api-contract.yaml`，再修改前后端和测试。
- 运行路径或数据命名变化时，同步更新根 README、`guides/运行配置与数据目录.md`、示例环境变量和真实测试命令。
- 功能完成后更新 `plans/开发计划与当前进度.md`，不把“代码存在”写成“用户真机验证通过”。
- 新验证报告放入 `reports`，记录输入文件 SHA-256、命令、环境、统计和保证边界。
- 新方案放入 `plans`，操作步骤放入 `guides`，稳定约定或契约放入 `reference`。
