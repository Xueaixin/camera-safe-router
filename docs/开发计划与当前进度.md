## 3. 摄像头自动化剩余工作

剩余开发任务：

1. 增加人工选择备份版本的回滚入口，复用候选校验和原子发布流程。
2. 接入连续失败监控告警。

生产环境的数据源许可确认、定时运行观察、阈值确认和摄像头坐标控制点核验由使用方执行，不计入后续编码任务。摄像头源仍按原始字节 SHA-256 比较；数组顺序、字段顺序或排版发生变化时视为新版本并重新构建快照，不增加业务内容指纹。

完成定义：远程失败或坏数据不能污染当前文件；服务持续使用上一有效快照；报告明确原始条数、过滤条数、匹配数和版本哈希。

### 4.1 跨区域路线算法备注

北京、天津、河北已经能够使用同一份路网稳定规划并继续硬避开摄像头。正式路线接口已经接入六环跨界策略，但当前边界仍以未批准候选状态加载。

当前冻结的业务规则不是强制使用六环高速：环内到环外优先尽快穿过外侧边界，环外到环内尽可能晚穿过内侧边界；在最短环内合规距离的绝对 1000 米容差内，再按完整参考路线选择大方向。六环高速、收费站和高速出入口都不是强制途经点。

边界闭环、生产通行口拓扑、多目标搜索、合规距离 profile、正式接口和多方向真实自动回归已证明基础方案可行。剩余发布阻断项是路线形状与特殊/保留候选的人工审批，而不是 GraphHopper 基础配置或接口接线。

详细方案见 [六环边界路线规划算法方案](六环边界路线规划算法方案.md)，本轮结果见 [六环东南西北真实路线回归报告](六环东南西北真实路线回归报告.md)。

## 5. 远期导航阶段

网页可以继续显示实时位置，但正式导航需要评估原生 App 或跨端方案，重点包括：

- 前后台连续定位权限和系统生命周期。
- 偏航检测与自动重新规划节流。
- 路口级指令、语音播报和航向。
- 弱网、离线、锁屏和省电策略。
- 用户隐私、轨迹最小化和数据保留政策。

后端 API 应保持客户端无关；导航扩展不应破坏当前 Web 手动重算契约。

## 6. 当前优先级

1. 人工查看 12 条正式规划器真实回归路线形状，后续复核 4 个保留位置和特殊拓扑候选。
2. 根据人工结果冻结边界带规则，并将边界文件的生产批准状态作为发布门槛。
3. 明确并实现 `EXTERNAL_ONLY` 的最终前端交互；当前后端返回本地参考路线，前端仍绘制完整 `geometry`，尚未自动切换高德导航。
4. 需要产品展示时再增加前端分段样式；当前继续使用完整 `geometry`，协议层已经保留分段数据。
5. PBF 月更、自动发布、摄像头人工回滚、连续失败告警、CI 和部署工程化暂缓，不占用当前线路规划主线。

## 7. 发布阻断条件

出现任一情况不得称为可发布：

- 成功路线的 `cameraConflictCount` 非零。
- 禁行没有发生在 GraphHopper 搜索期间。
- QueryGraph 可以绕过禁行基础边。
- PBF 与缓存哈希不一致。
- 新摄像头数据未经校验或更新失败时覆盖旧快照。
- 前端直接把 WGS84 定位绘制到高德地图。
- 手动重新规划失败后清空旧路线。
- 真实 Key、证书、PBF、缓存或快照进入 Git。
- 未执行的 IDE、构建或手机验证被描述为已经通过。
- 未审批的保留通行口被静默视为生产可用。
