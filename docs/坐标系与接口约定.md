# 坐标系与接口约定

## 1. 唯一契约

[api-contract.yaml](api-contract.yaml) 是前后端唯一机器可读 HTTP 契约。本文解释关键语义，不替代 OpenAPI 字段、必填项和状态码定义。

修改流程：先更新 OpenAPI 和共享夹具，再修改后端、前端类型及双方测试。不得只改某一端来“兼容”未确认的协议漂移。

## 2. 坐标系统

| 来源或消费者 | 坐标系 | 处理方式 |
|---|---|---|
| 浏览器 Geolocation | WGS84 | 原样保留为规划起点，展示前转 GCJ-02 |
| OSM PBF / GraphHopper / JTS | WGS84 | 后端内部唯一计算坐标 |
| 高德搜索、点选和地图展示 | GCJ-02 | 请求中显式标记；后端转 WGS84 |
| 摄像头原始接口 | 当前假定 GCJ-02 | 加载时同时保存原始 GCJ-02 与转换后的 WGS84 |
| 路线 API 响应几何 | GCJ-02 | 前端可直接绘制到高德地图 |

`GCJ02` 是 API 枚举值，文档中可写作 GCJ-02。经纬度顺序始终是 `lng` 后 `lat`。

## 3. 坐标来源

路线端点除坐标系外还应携带来源：

| 来源 | 典型坐标系 | 说明 |
|---|---|---|
| `CURRENT_LOCATION` | WGS84 | 浏览器最近一次有效位置 |
| `AMAP_SEARCH` | GCJ-02 | 高德地点搜索结果 |
| `MAP_PICK` | GCJ-02 | 高德地图点击选点 |

手动重新规划必须使用最新 `CURRENT_LOCATION` 起点和原终点，不能把地图展示用 GCJ-02 位置误当浏览器原始 WGS84。

## 4. 转换边界

- 前端同时保留浏览器原始 WGS84 和地图展示 GCJ-02，不能覆盖成一个无坐标系的通用对象。
- 后端收到请求后先校验范围，再统一转成 WGS84 进入路由和 JTS。
- 后端返回前把路线几何转成 GCJ-02，并设置顶层 `coordinateSystem`。
- 禁止根据经纬度数值大小猜测坐标系；二者在北京通常相差数百米但数值格式相同。
- 控制点人工验证未完成前，摄像头 GCJ-02 仍是高可信假设，不是正式数据方声明。

## 5. 路线安全契约

成功响应必须同时满足：

- HTTP 为成功状态。
- `coordinateSystem = GCJ02`。
- `geometry` 至少两个点。
- `cameraConflictCount = 0`。
- `cameraSnapshotVersion` 与 `blockedEdgeVersion` 非空。

如果后端最终校验发现冲突，必须返回 `ROUTE_CONFLICT_DETECTED`，不能返回带非零冲突数的成功体。前端仍需做协议防御，拒绝绘制任何非零冲突“成功”响应。

## 6. 业务错误

后端当前错误码：

| 错误码 | 前端行为 |
|---|---|
| `INVALID_REQUEST` | 提示输入不完整或格式错误 |
| `INVALID_COORDINATE` | 提示坐标无效 |
| `UNSUPPORTED_COORDINATE_SYSTEM` | 拒绝请求并提示坐标系不支持 |
| `OUTSIDE_ROUTING_BOUNDS` | 提示超出当前京津冀路网范围 |
| `START_IN_RESTRICTED_AREA` | 提示起点落入限制范围 |
| `END_IN_RESTRICTED_AREA` | 提示终点落入限制范围 |
| `NO_COMPLIANT_ROUTE` | 不绘制新路线；重新规划时保留旧路线 |
| `ROUTE_SEARCH_TIMEOUT` | 提示搜索超时并允许重试，不解释为无路 |
| `ROUTE_SEARCH_RESOURCE_LIMIT` | 提示达到资源上限并允许重试，不解释为无路 |
| `SIXTH_RING_TOPOLOGY_NOT_READY` | 提示六环边界和通行口仍在初始化 |
| `SIXTH_RING_BOUNDARY_AMBIGUOUS` | 提示调整位于六环边界带的起点或终点 |
| `REFERENCE_ROUTE_FAILED` | 提示环内可达但完整参考路线生成失败 |
| `ROUTE_CONFLICT_DETECTED` | 视为后端安全校验阻断，不绘制路线 |
| `ROUTING_NOT_READY` | 提示路网仍在初始化 |
| `CAMERA_SNAPSHOT_NOT_READY` | 提示摄像头快照未就绪 |
| `CAMERA_QUERY_RESULT_LIMIT_EXCEEDED` | 保留现有点位并提示放大地图后重试 |
| `REFRESH_ALREADY_RUNNING` | 提示刷新正在进行 |
| `CAMERA_UPDATE_ALREADY_RUNNING` | 提示摄像头远程更新正在进行 |
| `CAMERA_UPDATE_FAILED` | 提示更新未生效，当前有效快照继续服务 |
| `INTERNAL_ERROR` | 显示通用服务错误，不暴露堆栈 |

前端按 `code` 分支，不解析后端 `message` 文本作为业务逻辑。

## 7. 快照一致性

一次路线请求从开始到完成只能使用一个不可变 `RoutingSnapshot`，包含：

- 摄像头源版本和哈希。
- 摄像头空间索引。
- GraphHopper 图指纹。
- 安全半径。
- 正反方向禁行 edge 集合。
- 匹配数和未匹配 ID。

刷新只有在新 JSON 校验、道路匹配、禁行集合和持久化元数据全部成功后才原子发布。失败时旧快照继续服务。

## 8. 人工坐标验收

正式确认摄像头源坐标前，至少选择 20 个地址明确的控制点：

1. 把原始点显示在高德地图，检查与道路和描述是否一致。
2. 把原始点直接显示在 OSM，记录偏移方向和距离。
3. 把 GCJ-02 转 WGS84 后显示在 OSM，再次检查。
4. 覆盖城区、郊区、路口、主辅路、高架和匝道。
5. 多数点支持同一结论后，记录数据版本、截图和异常点。

自动匹配率只能提供统计证据，不能替代这一人工验收。
