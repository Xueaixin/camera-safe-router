# 代码结构与核心流程

本文说明当前仓库的代码组织、模块职责和主要调用链。产品边界看 [产品需求与技术方案](../plans/产品需求与技术方案.md)，运行路径看 [运行配置与数据目录](../guides/运行配置与数据目录.md)，HTTP 字段以 [api-contract.yaml](api-contract.yaml) 为准。

## 1. 仓库边界

```text
camera-safe-router/
├─ README.md                 项目入口、启动方式和当前状态
├─ docs/                     当前设计、契约、计划和验证报告
├─ scripts/                  数据目录初始化和性能验证脚本
├─ server/                   Spring Boot + GraphHopper 后端
└─ web/                      Vue 3 + 高德地图前端
```

PBF、`camera.json`、GraphHopper 缓存、禁行边快照和备份都在仓库外的数据根目录中。代码不能依赖 IDE 工作目录中的真实数据文件。

## 2. 后端结构

后端源码根目录为 `server/src/main/java/cn/camera/safe`：

```text
cn.camera.safe/
├─ CameraSafeRoutingApplication.java  启动类、配置绑定和定时调度开关
├─ api/                               HTTP 控制器、错误处理和请求 ID
│  └─ model/                         API 请求与响应模型
├─ application/                       用例编排和服务生命周期
├─ camera/                            摄像头加载、过滤、快照和空间索引
│  └─ update/                        远程下载、定时更新、备份和原子发布
├─ config/                            配置属性和线程池
├─ coordinate/                        WGS84/GCJ-02 类型、转换和校验
├─ routing/                           GraphHopper、道路索引、禁行边和路由快照
└─ validation/                        返回路线的独立空间安全校验
```

### 2.1 包职责

| 包 | 职责 | 代表类 |
|---|---|---|
| `api` | 接收和校验 HTTP 请求，调用应用服务，统一输出错误 | `RouteController`、`CameraController`、`OperationsController`、`GlobalExceptionHandler` |
| `api.model` | 与 OpenAPI 对应的输入输出数据，不放业务算法 | `RouteRequest`、`RouteResponse`、`BoundaryCrossing`、`NavigationHandoff`、`ExternalHandoff`、`RouteSegment` |
| `application` | 组织一次完整用例，不实现底层空间算法 | `RoutePlanningService`、`CameraQueryService`、`BackendInitializer` |
| `camera` | 解析摄像头源、执行 `IsSixRingOut != 1` 过滤、建立不可变快照和查询索引 | `CameraJsonLoader`、`CameraSnapshot`、`CameraSpatialIndex` |
| `camera.update` | 从远程接口获取候选数据，校验、备份、发布和清理历史文件 | `CameraUpdateScheduler`、`CameraUpdateService`、`CameraSourceClient`、`CameraUpdateFileStore` |
| `coordinate` | 用类型区分坐标系并集中转换，防止 WGS84 和 GCJ-02 混用 | `CoordinateConverter`、`Wgs84Coordinate`、`Gcj02Coordinate` |
| `routing` | 管理路网、道路分类索引、搜索期硬禁边、控制释放拓扑、道路状态跨界约束、多目标规划和版本化路由快照 | `GraphHopperManager`、`RoadClassificationIndex`、`ControlReleaseTopologyBuilder`、`SixthRingRoutePlanner`、`RoadStateTraversalConstraint`、`RoutingSnapshotManager` |
| `validation` | 在 GraphHopper 返回路线后按有向 trace 独立确认道路状态合法和适用摄像头规则零冲突 | `SixthRingRouteShapeValidator`、`RouteSafetyValidator` |
| `config` | 绑定 `application.yml` 并创建有界执行器 | `AppProperties`、`ExecutorConfiguration` |

依赖方向通常是 `api -> application -> camera/routing/validation`。底层路由和摄像头代码不依赖 Controller；`OperationsController` 只为 health、readiness 和本机管理操作直接读取运行状态。

### 2.2 关键运行对象

| 对象 | 生命周期和作用 |
|---|---|
| `GraphHopperManager` | 进程内单例；按 profile 选择隔离缓存，校验 PBF/配置指纹，加载或构图并持有道路索引 |
| `RoutingGraphConfiguration` | 定义合规路由 profile、turn costs、road_access 规则、道路身份编码和缓存兼容指纹 |
| `SixthRingBoundary` | 保存经过版本标识的六环内侧与通州并集 Polygon/MultiPolygon，并提供受控区空间谓词 |
| `SixthRingPortal` | 表示一个可搜索的有向边界通行状态，保留 edge key、方向、边上比例、边界节点和候选类型 |
| `SixthRingPortalTopologyBuilder` | 从当前 GraphHopper 图生成边内部、边端和边界重叠链通行口，并在节点转换时检查单向访问和 turn costs |
| `SixthRingPortalTopology` | 分别保存出环和入环候选及相交边、重叠边、边界节点和歧义边统计 |
| `SixthRingRoutingManager` | 在 GraphHopper 就绪后加载版本化边界、校验 PBF 哈希并构建当前有向通行口拓扑 |
| `RoadClassificationIndex` | 以原始基础边为键保存六环/通州高速主路、匝道和受控/非受控道路身份；QueryGraph 虚拟边映射回原始边 |
| `ControlReleaseTopologyBuilder` | 从普通道路物理边界交点生成有向控制释放点，并保留转换上下文；受控区高速不作为普通释放点 |
| `SixthRingRoutePlanner` | 自动判定四种规划模式；场景 3 按 `Dmin + 1000 米` 分层搜索释放点，再按完整时间、完整距离和受控距离选择合法完整路线 |
| `EdgeKeyMultiTargetDijkstra` | 使用到达 edge key 作为状态，支持 turn costs、禁行边、反向搜索、QueryGraph 虚拟边、通行口 edge 前缀约束和资源上限 |
| `RoadStateTraversalConstraint` | 区分六环主路、六环内其他高速、六环外通州高速、匝道和普通道路；执行收费站待定出界与高速互转的有向状态约束 |
| `TraversalConstrainedWeighting` | 将每请求边界约束包装进 GraphHopper Weighting，不改变无约束场景 |
| `RouteTraceSupport` | 从标准路线和拼接路线保留有向基础边 trace；入界路线在规范终检前反转为界内到界外方向 |
| `SixthRingRouteShapeValidator` | 用有向 trace 状态机终检控制释放后不得进入受控普通道路；JTS 只校验物理边界交点和分段连续性 |
| `BoundaryCrossingResolver` | 从最终 trace 推导物理并集边界交点；出界取最早一次有效出界，入界取实际行驶方向最后一次有效入界 |
| `PortalAnchoredRouteFinder` | 从已选通行口的真实有向 edge 拓扑继续搜索参考段，禁止按相同平面坐标跳到桥下或桥上道路 |
| `NavigationHandoffSelector` | 优先选择最终参考路线界外 500 米内的普通道路点；仅入界且普通道路为空时，在界外高速主路上选择约 300 米兜底点，排除 link、隧道和轮渡 |
| `ExternalHandoffSelector` | 普通道路点按边界净空计算 POI 半径；高速点固定返回 0，禁止附近 POI 替换 |
| `RoutingSnapshot` | 不可变；把源摄像头、受控摄像头索引、道路分类指纹、边界版本、50 米参数和当前禁行边绑定为同一版本 |
| `RoutingSnapshotManager` | 用原子引用发布当前快照，用互斥锁防止刷新和远程更新并发切换 |
| `RoutingSnapshotStore` | 把禁行 edge ID 和版本信息写入外部 `snapshots` 目录，按内容去重并限量保留 |
| `CameraUpdateService` | 同步执行一次完整远程更新；定时任务和手动接口复用它 |

## 3. 后端核心流程

### 3.1 服务启动

```mermaid
flowchart LR
    A["ApplicationReadyEvent"] --> B["BackendInitializer"]
    B --> C["GraphHopperManager.initialize"]
    C --> D["加载缓存或从 PBF 构图"]
    D --> E["建立 RoadEdgeIndex"]
    E --> F["SixthRingRoutingManager.initialize"]
    F --> G["加载并集边界并构建有向通行口"]
    G --> H["构建道路分类索引和控制释放拓扑"]
    H --> I["审计六环与通州高速道路分类"]
    I --> J["RoutingSnapshotManager.refreshNow"]
    J --> K["读取 cameras/camera.json"]
    K --> L["按受控区与界外50米过滤并匹配道路"]
    L --> M["豁免高速主路并持久化 RoutingSnapshot"]
    M --> N["readiness = READY"]
```

启动流程不访问远程摄像头接口。远程接口失败不会阻止服务根据现有 `camera.json` 恢复路线能力。历史 `routing-snapshot-*.json` 用于审计，不会直接反序列化为进程内快照，因为 edge ID 必须与当前图缓存重新确认。

### 3.2 路线规划

```text
POST /api/v1/routes
  -> RouteController
  -> RoutePlanningService
  -> 输入坐标统一转换为 WGS84
  -> 检查路网范围和起终点限制
  -> SixthRingRoutePlanner 自动判定四种模式
  -> INTERNAL_SAFE：GraphHopperRoutingEngine 全局搜索，不施加受控区域空间限制
  -> 跨界路线：QueryGraph + EdgeKeyMultiTargetDijkstra 在受控侧按合规道路距离搜索普通道路释放点
  -> 首层保留 Dmin + 1000 米；无完整合法路线时按 1000 米逐层扩展
  -> 控制释放点位于 edge 内部时只允许遍历到释放位置的前缀
  -> 释放阶段按 RoadStateTraversalConstraint 区分 R/H-S/H-T/O 与有向匝道链
  -> H-S 永久禁行；R/H-T 允许几何出界再入界，但不得落到受控普通道路
  -> 六环收费站共享段进入 EXIT_PENDING，最终分叉到界外才接受
  -> SixthRingRouteShapeValidator 按最终有向 edge trace 独立执行同一状态终检
  -> 按完整时间、完整距离、受控侧距离和释放点 ID 决胜
  -> BoundaryCrossingResolver 从最终 trace 推导物理并集边界交点
  -> 从最终路线界外方向 500 米内优先选择严格界外普通道路 navigationHandoff
  -> 仅入界普通道路为空时，在界外高速主路上选择约 300 米 HIGHWAY 交接点
  -> externalHandoff 与 navigationHandoff 同坐标；普通道路使用动态 POI 半径，高速固定为 0
  -> navigationHandoff 非空时在该点切分 safeSegment / referenceSegment
  -> RouteSafetyValidator 只对非高速主路 trace 独立检查适用摄像头规则冲突
  -> 输出转换为 GCJ-02
  -> RouteResponse(技术边界点 + 可选道路交接点 + 外部审计点 + 分段路线 + 完整 geometry，cameraConflictCount = 0)
```

`BlockedEdgeWeighting` 在搜索阶段拒绝适用摄像头规则的禁行基础边及其 QueryGraph 虚拟边；六环和通州高速主路不写入禁行位图，但 OSM access、单行线、turn restriction 和道路关闭状态仍生效。`RoadStateTraversalConstraint` 是搜索期硬约束，trace 状态终检和摄像头 JTS 终检是独立第二道检查。`EXTERNAL_ONLY` 没有 `safeSegment`，只返回完整外部参考路线；落在权威边界线上的端点返回独立歧义错误。

### 3.3 摄像头查询

```text
GET /api/v1/cameras
  -> CameraController
  -> CameraQueryService
  -> 当前 RoutingSnapshot.cameraIndex
  -> bbox 查询
  -> 按实际命中数量检查响应上限，不限制 bbox 经纬度跨度
  -> 按请求坐标系输出 CameraPage
```

查询只读取当前不可变快照，不直接扫描 `camera.json`，因此不会与文件更新互相阻塞。

### 3.4 摄像头自动更新

```mermaid
flowchart TD
    A["CameraUpdateScheduler 或本机管理接口"] --> B["CameraUpdateService 防重入"]
    B --> C["CameraSourceClient POST 下载"]
    C --> D{"SHA-256 是否相同"}
    D -->|是| E["返回 NO_CHANGE"]
    D -->|否| F["写入 downloads/cameras 候选"]
    F --> G["从候选构建完整 RoutingSnapshot"]
    G --> H["检查数量变化、匹配率和禁行边变化"]
    H --> I["持久化候选禁行边快照"]
    I --> J["备份当前 camera.json"]
    J --> K["原子替换 camera.json"]
    K --> L["原子切换进程内快照"]
    L --> M["清理超量备份、快照和失败候选"]
```

候选构建或校验失败时，正式文件和当前内存快照都不变化。文件替换与内存快照发布共用 `RoutingSnapshotManager` 的排他锁，避免与 `/admin/camera-snapshots/refresh` 交叉发布。

## 4. 前端结构

前端源码根目录为 `web/src`：

```text
web/src/
├─ main.ts                    Vue 和 Pinia 入口
├─ app/App.vue                页面装配、启动和跨模块事件协调
├─ components/
│  ├─ map/                    地图、路线、摄像头和当前位置图层
│  └─ route/                  起终点输入、结果摘要和步骤面板
├─ composables/               地图视口摄像头加载和浏览器定位
├─ stores/                    route、location、map 三类页面状态
├─ services/                  API 接口、HTTP 实现、协议校验和错误类型
├─ maps/                      高德与 mock 地图适配器
├─ types/                     API、坐标和地图 TypeScript 类型
├─ config/                    环境变量和定位策略
├─ mocks/                     mock API 与数据夹具
└─ styles/                    全局 token 和布局样式
```

### 4.1 前端职责

| 目录 | 职责 |
|---|---|
| `components` | 展示和用户交互；不直接拼装 HTTP 请求 |
| `stores` | 保存跨组件状态并编排路线请求、定位状态和地图状态 |
| `services` | 屏蔽真实 HTTP 与 mock API 差异，校验后端协议 |
| `maps` | 屏蔽高德 SDK 与 mock 地图差异，统一地图操作接口 |
| `composables` | 管理带生命周期的浏览器行为，例如视口防抖、请求取消和定位监听 |
| `types` | 集中定义坐标、API 和地图边界，避免组件内重复声明 |

路线交互的主要数据流是：

```text
RouteSearchPanel
  -> routeStore.plan / rerouteFromLocation
  -> ApiClient
  -> HttpApiClient 或 MockApiClient
  -> 协议和坐标系校验
  -> routeStore.route
  -> RouteLayer 绘制完整 geometry，并仅为 navigationHandoff 创建交接标记
  -> RouteSummarySheet 切换完整行程 / safeSegment
  -> 地图交接点弹窗显示 navigationHandoff 道路
  -> 围绕 navigationHandoff 按 externalHandoff.poiSearchRadiusMeters 动态半径解析交通地标
  -> 提供复制地标和精确高德导航
```

浏览器定位原始值保留为 WGS84，用于后端路线请求；绘制到高德地图前由地图适配器转换为 GCJ-02。两个值分别保存在 `locationStore.browserLocation` 和 `locationStore.displayLocation`。

## 6. 常见改动落点

| 需求 | 首要修改位置 | 必须同步检查 |
|---|---|---|
| 新增或修改 HTTP 接口 | `docs/reference/api-contract.yaml`、`api/model`、对应 Controller | application 服务、前端 `types/api.ts`、API 客户端和契约测试 |
| 修改路线安全规则 | `routing`、`validation` | `RoutePlanningService`、真实路线测试和技术方案 |
| 修改摄像头字段或过滤规则 | `camera/CameraJsonLoader` | 加载器测试、真实文件测试、匹配报告和更新校验 |
| 修改自动更新策略 | `camera/update`、`AppProperties`、`application.yml` | 本机管理接口、保留策略测试和自动化更新文档 |
| 修改坐标处理 | `coordinate` | API 模型、前端地图适配器、控制点和路线测试 |
| 修改路线页面交互 | `components/route`、`components/map`、`stores/routeStore.ts` | 地图适配器、API 错误映射、组件测试和 Playwright |
| 修改地图图层或视口加载 | `components/map`、`maps`、`composables` | 坐标系约束、请求取消和视口测试 |

新增代码应先判断属于 HTTP 适配、用例编排、领域数据、路由算法还是 UI 状态，放入对应边界；不要把下载、文件操作或 GraphHopper 细节写进 Controller，也不要让 Vue 组件直接依赖高德 SDK 的全局对象。
