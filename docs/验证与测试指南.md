# 验证与测试指南

## 1. 验证层级

| 层级 | 目的 | 是否需要真实外部服务 |
|---|---|---|
| 单元/组件测试 | 业务分支、协议、坐标和 UI 状态 | 否 |
| 真实文件测试 | PBF 导图、摄像头匹配、缓存和零冲突路线 | 需要本地 PBF/JSON，不访问远程接口 |
| HTTP 联调 | 前后端契约、状态码和手动重算 | 需要本地后端 |
| 高德/桌面联调 | 地图、搜索和渲染 | 需要高德 Key 和网络 |
| 手机 HTTPS | 定位权限、响应式和局域网 | 需要可信证书和真机 |

验证结果必须注明所处层级。mock 通过不等于真实高德或真机通过。

## 2. 准备数据路径

从 `code` 目录执行：

```powershell
.\scripts\init-data-directory.ps1
$driveRoot = [System.IO.Path]::GetPathRoot((Resolve-Path .).Path)
$routingDataRoot = Join-Path $driveRoot 'camera-safe-routing-data'
$pbf = Join-Path $routingDataRoot 'osm\jingjinji-latest.osm.pbf'
$cameraJson = Join-Path $routingDataRoot 'cameras\camera.json'
Get-FileHash -Algorithm SHA256 -LiteralPath $pbf, $cameraJson
```

当前京津冀 PBF 预期 SHA-256：

```text
2a1bcebc16586858bc116a67dd10b9e5191241bbbb096866d0d0a2538ca16131
```

当前摄像头 JSON 预期 SHA-256：

```text
0c16ed44ef2e24cd4759afba28d6448925db699a4d3b38b05980f076e6ac7404
```

哈希不同不一定代表文件错误，但不能再套用本文的固定统计，必须生成新报告。

## 3. 后端默认测试和构建

```powershell
Set-Location .\server
java -version
mvn -version
mvn test
mvn package
```

默认测试不需要真实 PBF；需要系统属性的真实测试会明确跳过。验收条件：Maven 成功、无失败和错误，跳过项仅为未提供真实文件的显式测试。

路径配置专项测试：

```powershell
mvn "-Dtest=RuntimePathConfigurationTest" test
```

该测试验证默认路径都位于 `/camera-safe-routing-data`，并验证只设置 `ROUTING_DATA_ROOT` 时四个路径一起迁移。

## 4. 真实摄像头 JSON 验证

```powershell
mvn `
  "-Dreal.camera.json=$cameraJson" `
  "-Dtest=RealCameraJsonTest" `
  test
```

当前全量文件预期 6,803 条并匹配固定哈希。生产过滤应断言排除 1,096 条 `IsSixRingOut=1`、保留 5,707 条，并单独记录 7 条字段缺失或非法记录；不得篡改原始文件让测试通过。

坐标控制点候选：

```powershell
mvn `
  "-Dcontrol.camera.json=$cameraJson" `
  "-Dtest=CoordinateControlPointReportTest" `
  test
```

输出在 `server/target/generated-coordinate-control-points.md`。该文件只是候选表，必须由用户在高德和 OSM 人工填写结论。

## 5. GraphHopper 硬避让 POC

```powershell
mvn `
  "-Dpoc.pbf=$pbf" `
  "-Dtest=RealPbfHardAvoidancePocTest" `
  test
```

验收点：

- PBF 能在 JUnit 临时目录导入。
- 基线路线存在。
- 禁用一条内部基础边后，新路线不再包含该边。
- 搜索审计记录到 `blockedRejections > 0`。
- 缓存关闭后可以重新加载并规划。

这证明禁边发生在搜索期，但不证明所有摄像头都匹配到语义正确的道路层级。

## 6. 真实快照和零冲突路线

```powershell
mvn `
  "-Dreal.pbf=$pbf" `
  "-Dreal.camera.json=$cameraJson" `
  "-Dtest=RealRoutingSnapshotIntegrationTest" `
  test
```

当前京津冀 PBF 的生产过滤口径基线：

| 半径 | 保留摄像头 | 匹配 | 未匹配 | 禁行边 |
|---:|---:|---:|---:|---:|
| 30 米 | 5,707 | 5,688 | 19 | 19,731 |

北京到天津、石家庄、张家口以及天津到石家庄四条代表路线均为零冲突。20/50 米分档报告尚未针对京津冀图重新生成，不能继续套用历史北京基线。

## 7. 摄像头匹配度报告

报告测试会重新导图并计算全量 20/30/50 米、生产过滤口径、未匹配点坐标和最近道路距离。为避免测试 JVM 按机器内存比例预留过大堆，显式限制为 1 GB：

```powershell
mvn `
  "-DargLine=-Xmx1024m -Dfile.encoding=UTF-8 -Djava.io.tmpdir=$PWD\target" `
  "-Dreport.pbf=$pbf" `
  "-Dreport.camera.json=$cameraJson" `
  "-Dreport.output=..\docs\新路网摄像头匹配验证报告.md" `
  "-Dtest=CameraMatchingReportTest" `
  test
```

报告验收：

- 文件使用中文名和 UTF-8。
- 记录 PBF/JSON 路径、大小和 SHA-256。
- 记录 GraphHopper 节点、边、可驾车索引边和边界。
- 记录 20/30/50 米匹配数和禁行边数。
- 单独记录 `IsSixRingOut!=1` 保留数量、异常标记数量和 30 米结果。
- 列出全量和正式口径未匹配明细。
- 明确坐标假设和匹配结果的保证边界。

匹配表示 30 米内至少存在可驾车基础边，不等于主辅路、高架层级和方向已人工确认。

## 8. 后端启动与 HTTP 冒烟

建议 VM options：

```text
-Xms1g -Xmx2g
```

PowerShell 启动：

```powershell
mvn spring-boot:run
```

首次启动导图时 `/health` 可以成功而 `/readiness` 暂时返回 503。就绪后：

```powershell
Invoke-RestMethod http://localhost:8080/api/v1/health
curl.exe -i http://localhost:8080/api/v1/readiness
Invoke-RestMethod http://localhost:8080/api/v1/camera-snapshots/current
```

固定路线请求：

```powershell
$body = @{
  start = @{
    lng = 116.3975
    lat = 39.9087
    coordinateSystem = 'WGS84'
    source = 'CURRENT_LOCATION'
  }
  end = @{
    lng = 116.4700
    lat = 39.9920
    coordinateSystem = 'WGS84'
    source = 'MAP_PICK'
  }
  vehicle = 'CAR'
} | ConvertTo-Json -Depth 4

$route = Invoke-RestMethod `
  -Method Post `
  -Uri 'http://localhost:8080/api/v1/routes' `
  -ContentType 'application/json; charset=utf-8' `
  -Body $body

if ($route.cameraConflictCount -ne 0) {
  throw "Unsafe route: cameraConflictCount=$($route.cameraConflictCount)"
}
$route | Select-Object routeId,distanceMeters,durationSeconds,cameraConflictCount
```

还应验证：起点限制、终点限制、超出路网、服务未就绪和无合规路线均返回 OpenAPI 定义的错误体。

## 9. 摄像头刷新验证

刷新仅允许本机调用：

```powershell
$before = Invoke-RestMethod http://localhost:8080/api/v1/camera-snapshots/current
$accepted = Invoke-RestMethod `
  -Method Post `
  http://localhost:8080/api/v1/admin/camera-snapshots/refresh
Start-Sleep -Seconds 3
$after = Invoke-RestMethod http://localhost:8080/api/v1/camera-snapshots/current
$before, $accepted, $after
```

验证刷新期间旧快照仍可用，成功后版本变化，失败时版本不变化。不要通过修改原始 JSON 制造失败，使用测试夹具或候选副本。

远程数据立即更新也只允许本机调用：

```powershell
$result = Invoke-RestMethod `
  -Method Post `
  http://localhost:8080/api/v1/admin/camera-data/update
$result | Format-List
```

响应为 `UPDATED` 时检查 `sourceRecordCount`、`retainedRecordCount`、`excludedRecordCount`、匹配数和哈希；远程内容与当前文件相同时返回 `NO_CHANGE`。验证 `backups/cameras` 中存在旧 `camera.json`，正式文件和当前快照哈希一致，超过配置上限的旧文件已清理。该调用会访问真实远程接口，默认测试套件不会执行。

内部定时任务默认关闭。测试部署可设置以下变量并重启后端，无需配置操作系统定时任务：

```text
CAMERA_UPDATE_ENABLED=true
CAMERA_UPDATE_CRON=0 15 3 * * *
CAMERA_UPDATE_ZONE=Asia/Shanghai
```

## 10. 前端测试和构建

```powershell
Set-Location ..\web
node --version
npm --version
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
```

首次运行 Playwright 可先安装浏览器：

```powershell
npx playwright install chromium
npm run test:e2e
```

重点自动测试：

- 协议校验拒绝非零冲突路线。
- 定位更新不发起路线请求。
- 手动重新规划使用最新 WGS84 位置和原终点。
- 重新规划失败保留旧路线。
- 迟到响应不覆盖较新请求。
- 摄像头 bbox 防抖和过期取消。
- 移动与桌面视口无明显重叠。

## 11. 前后端本地联调

`web/.env.local`：


保持 `VITE_API_BASE_URL` 为空时，Vite 把 `/api` 代理到 `127.0.0.1:8080`。依次启动后端和：

```powershell

```

## 12. 手机 HTTPS 和定位

浏览器 Geolocation 在手机局域网地址上通常要求可信 HTTPS。项目不会提交开发私钥；每台开发机单独生成。

Windows 推荐通过 winget 安装 mkcert：

```powershell
winget install FiloSottile.mkcert
```

winget 不可用时，可从 [mkcert 官方发行版](https://github.com/FiloSottile/mkcert/releases) 安装并加入 PATH。安装后重新打开 PowerShell。先运行 `ipconfig` 确认本机局域网 IPv4，再执行：

```powershell
Set-Location .\web
New-Item -ItemType Directory -Path .\certs -Force | Out-Null
mkcert -install
mkcert `
  -cert-file .\certs\dev-cert.pem `
  -key-file .\certs\dev-key.pem `
  localhost 127.0.0.1 ::1 <本机局域网IP>
npm run dev:https
```

手机需要信任对应开发根证书，并访问 `https://<本机局域网IP>:5173`。通过以下命令查看本机开发 CA 目录：

```powershell
mkcert -CAROOT
```

只将该目录中的 `rootCA.pem` 安装到自己的测试手机，不得复制或分享 `rootCA-key.pem`。Android 在系统安全设置中安装 CA 证书；iOS 安装描述文件后，还需在“设置 -> 通用 -> 关于本机 -> 证书信任设置”中启用完全信任。

同时检查：

- 手机与电脑在同一局域网。
- Windows 防火墙允许 Node/Vite 端口。
- 高德控制台允许当前开发来源。
- 浏览器站点位置权限为允许，而不是系统允许但站点阻止。
- 地址栏没有证书警告；有警告时 Geolocation 仍可能被拒绝。
- 证书包含当前局域网 IP；电脑 IP 变化后应重新生成证书。

真机至少验证竖屏、横屏、软键盘、定位精度圆、拖图不自动回中、回到当前位置和手动重新规划。

## 13. 性能验证

后端启动后：

```powershell
.\scripts\benchmark.ps1 -Iterations 50 -Warmup 5
```

记录首次导图、缓存加载、图缓存大小、路线 P50/P95、最慢无路请求和 JVM 堆。扩大到京津冀后必须重新测量，不能沿用北京数据指标。

前端在真实手机检查摄像头图层、路线折线、定位更新和底部面板是否卡顿。不要为每个摄像头创建一个 Vue 组件实例。

## 14. 最终验收记录

每次发布候选应保存：

- Git 提交或源码版本。
- PBF、摄像头 JSON 和报告 SHA-256。
- 后端/前端实际命令及结果。
- readiness 和路线响应版本。
- `cameraConflictCount=0` 证据。
- 未匹配点和人工坐标核验状态。
- IDEA、WebStorm、桌面浏览器和手机的已验证/未验证状态。
- 已知风险、回滚路径和下一步。
