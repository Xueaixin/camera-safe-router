# Agent 开发规范

## 1. 适用范围

本文约束使用 Codex 或其他代码 Agent 修改本仓库时的工作方式。目标是把需求、契约、文件所有权、测试证据和未验证项写清楚，减少跨会话漂移和伪实现。

## 2. 每个会话的必读顺序

1. `README.md`
2. `docs/README.md`
3. `docs/产品需求与技术方案.md`
4. `docs/运行配置与数据目录.md`
5. `docs/坐标系与接口约定.md`
6. `docs/开发计划与当前进度.md`
7. 与任务相关的源代码和测试

涉及数据更新时继续读取 `docs/自动化数据更新方案.md`；涉及联调或验收时读取 `docs/验证与测试指南.md` 和 `docs/api-contract.yaml`。

`docs/archive` 只用于历史追溯，不是当前实施依据。

## 3. 开工前检查

- 明确任务是分析、修复、实现还是验证；纯分析请求不得自动扩大为代码修改。
- 检查当前 Git 状态和未提交改动，保留用户及其他会话的工作。
- 搜索现有实现和测试，优先沿用本项目模式。
- 写清任务的文件范围、共享契约影响、真实数据依赖和完成定义。
- 大任务先拆成可以独立验证的子任务，避免一个会话同时重写前端、后端、数据和文档。
- 任何会改变 API、坐标、硬避让或数据发布语义的决定，先在文档和测试中明确。

## 4. 推荐任务边界

| 会话类型 | 默认文件范围 | 必须输出 |
|---|---|---|
| 前端 | `web/**`、对应前端文档 | UI 状态、协议测试、构建结果、真实地图待验证项 |
| 后端 | `server/**`、对应后端文档 | API/路由实现、单元测试、真实数据测试入口、资源影响 |
| 数据自动化 | 未来 updater 模块、脚本、自动化文档 | 原子发布、校验、回滚、幂等和调度说明 |
| 契约/总控 | `docs/api-contract.yaml`、共享文档和双方契约测试 | 兼容性分析、迁移步骤和联调结果 |
| 验证审查 | 原则上只读；确认后修复所属范围 | 问题清单、证据、已执行命令和残余风险 |

需要跨边界修改时，先说明原因和受影响会话；不要顺手重构无关模块。

## 5. 不可破坏的技术约束

- 成功路线必须 `cameraConflictCount = 0`。
- 摄像头避让必须发生在 GraphHopper 搜索期，并保留 JTS 独立最终校验。
- QueryGraph 虚拟边必须追溯原始基础 edge key。
- 找不到安全路线时返回业务错误，不返回已知违规路线。
- GraphHopper/JTS 使用 WGS84；高德展示使用 GCJ-02；浏览器定位原始值按 WGS84 保存。
- 定位更新只移动位置标记，不自动重新规划。
- 手动重新规划使用最新位置和原终点；失败保留旧路线。
- PBF、图缓存和禁行快照必须版本一致。
- 快照和数据更新失败时保留上一有效版本。
- 下一阶段正式摄像头口径是 `IsSixRingOut == "0"`，缺失和非法值不能默认为纳入。

任何绕过这些约束的“临时方案”都必须视为未完成，而不是降级实现。

## 6. 契约修改规则

`docs/api-contract.yaml` 是唯一 HTTP 契约。修改 API 时必须同一任务完成：

1. 说明兼容性和调用方影响。
2. 更新 OpenAPI。
3. 更新后端模型、Controller 和契约测试。
4. 更新前端类型、协议校验、客户端和组件测试。
5. 更新 mock 夹具。
6. 运行 OpenAPI 解析及前后端相关测试。

不得让 mock 比真实 API 多字段或使用不同错误码来掩盖联调问题。

## 7. 数据和配置规则

- 运行数据统一放在仓库外的 `camera-safe-routing-data`。
- 路径通过 `ROUTING_DATA_ROOT` 或单项变量配置，不写死开发机绝对路径。
- PBF 使用 `beijing-latest.osm.pbf`、`china-latest.osm.pbf`、`jingjinji-latest.osm.pbf` 命名。
- 不提交 PBF、图缓存、快照、下载临时文件、真实 `.env.local` 或 HTTPS 私钥。
- 不修改原始 `map.json` 来让测试通过；生成候选文件和报告时使用新路径。
- 更新 PBF 后必须使用新缓存并重新匹配摄像头，不能复用旧 edge ID。
- 自动任务必须先写临时文件、校验、原子发布，并提供可验证回滚。

## 8. 测试和证据

测试强度与影响范围匹配：

- 小型纯函数修改：相关单元测试和静态检查。
- API/状态修改：后端契约测试、前端协议/状态测试和 mock 一致性。
- 路由修改：方向、QueryGraph、无路、起终点限制和 JTS 回归。
- PBF 或匹配修改：真实 20/30/50 米报告、未匹配明细、固定零冲突路线和缓存加载。
- 定位/UI 修改：单元测试、Playwright 桌面/移动视口；真实手机权限由用户验收。
- 数据自动化：成功、下载中断、坏数据、数量异常、重复任务、原子替换失败和回滚测试。

交付时区分：

- “测试代码已添加”。
- “Agent 实际执行并通过”。
- “需要用户在 IDEA/WebStorm/手机执行”。

不得把 mock 地图、测试双替身或代码阅读描述成真实高德、真实 PBF或真机验证通过。

## 9. Agent 交付格式

每个实现会话结束时至少提供：

```text
1. 实现结果
2. 修改文件和边界
3. 契约或配置变化
4. 添加/更新的测试
5. Agent 实际运行的命令及结果
6. 用户需要执行的 IDEA/WebStorm/手机步骤
7. 用户需要补充的密钥、数据或环境变量
8. 已知限制、未验证项和下一步
```

报告中的路径使用仓库相对路径或统一数据根目录，不记录只在某台机器成立的绝对路径，真实验证报告的输入路径除外。

## 10. 多 Agent 协作

- 总控先冻结 API、坐标和文件所有权，再并行分配。
- 前后端可并行，但双方只通过 OpenAPI 和共享夹具对接。
- 一个 Agent 不覆盖另一个 Agent 的未提交修改。
- 子任务必须有独立验收标准，不把“完成整个项目”作为单个子任务。
- 总控最终检查 OpenAPI、坐标、错误码、mock、手动重算、越界修改和用户配置。
- 发生契约冲突时暂停合并，由总控确定迁移方案，不能各自增加兼容分支。

推荐拆分：

```text
总控
├─ 后端业务与契约
├─ 前端交互与契约
├─ 摄像头更新器
├─ OSM 下载和切分 POC
└─ 联调、真实数据回归与文档
```

## 11. Git 规则

- `server` 和 `web` 当前有历史嵌套 `.git`；统一根仓库建立前不得擅自删除、初始化或重写它们。
- 先检查状态，再修改；不使用 `git reset --hard` 或覆盖用户改动。
- 提交前检查 `.env.local`、证书、PBF、缓存、快照和构建目录未进入暂存区。
- 不为文档整理混入无关格式化和依赖升级。
- 自动生成报告可提交，前提是输入哈希、命令和保证边界完整，且不含秘密。

## 12. 任务提示词模板

```text
请先完整读取 README.md、docs/README.md、docs/Agent开发规范.md，
再读取本任务涉及的源码、测试和契约。

任务目标：<一个可独立验证的目标>
允许修改：<目录或文件>
禁止修改：<共享契约/另一端代码/真实数据>
必须保持：cameraConflictCount=0、坐标契约、失败保留旧状态等
验收：<明确测试、真实数据或 UI 状态>

先审查现状和风险，再实现；完成后列出实际执行的测试、未验证项和用户配置。
```
