## 1. 目标与适用范围

系统继续作为高德导航的辅助系统：在适用道路严格避让摄像头、仅对明确允许的高速主路豁免摄像头的前提下，优先缩短受控普通路段的合规道路距离，再用本地完整参考路线时间判断合理的出入界方向。受控区域外最终以高德导航为准，本地界外路线不承担实时路况导航保证。

本方案适用于四种模式：

| 起点 | 终点 | 模式 | 核心目标 |
|---|---|---|---|
| 界外 | 界外 | `EXTERNAL_ONLY` | 本地路线只作参考，实际导航以高德为准 |
| 界内 | 界内 | `INTERNAL_SAFE` | 在全部硬约束下按时间优先、距离其次选择；必要时允许出界后再入界 |
| 界内 | 界外 | `CROSS_BOUNDARY_OUTBOUND` | 优先尽快离开受控区域，并用完整参考路线校正出口方向 |
| 界外 | 界内 | `CROSS_BOUNDARY_INBOUND` | 优先尽晚进入受控区域，并用完整参考路线校正入口方向 |

## 2. 已冻结的业务决定

1. 新受控区域为“六环主路内侧闭环”和“通州区行政区域”的面并集；六环主路本身不包含在六环受控内区中。
2. 边界通行口基于新并集边界生成，不再基于收费站或高速出入口名单生成。
3. 技术边界交点位于边界线上；用户可操作的高德导航交接点必须严格位于并集边界外。
4. 受控区内、边界上以及界外 50 米安全边距内的摄像头，只对非高速主路边生成硬禁行；超过 50 米的界外摄像头解禁。
5. 六环高速主路允许通行且完全不受摄像头限制，但 OSM access、单行线、施工/封闭状态和 turn restriction 继续生效。
6. 通州区内高速主路采用与六环主路相同的摄像头豁免；“高速主路”不包括高速匝道。
7. 场景 3 的跨界候选使用受控侧合规道路距离窗口：先求 `Dmin`，首层保留 `Dcontrolled <= Dmin + 1000 米` 的候选。
8. 首层无完整合法路线时，以 1000 米为步长继续扩展距离层；`Tmin + 180 秒` 不再参与场景 3 的业务选择。
9. 高德导航交接点沿最终路线的最大寻找范围首版为 500 米。
10. 完整参考路线的预计时间来自本地 OSM/GraphHopper，不包含高德实时路况。
11. 普通道路交接点不可用时，只允许 `CROSS_BOUNDARY_INBOUND` 在严格界外高速主路上使用交接点兜底。
12. 跨界路线不再执行纯几何“出界后不得入界”；改为分区道路状态约束：六环主路可以跨界，六环外通州区的允许高速可以通过无摄像头匝道互转，但六环内其他高速不得通行，六环内不得上下高速或通过匝道切换高速。
13. 跨界状态统一按“界内端点到界外端点”校验；实际入界请求反转有向边序列后使用同一规则，避免正反向出现不同业务口径。
14. 六环收费站必须按实际行驶方向分别识别入口走廊和出口走廊，不能把收费站复合体、匝道组件或收费节点设为无方向白名单。
15. 已经从界外普通道路释放的路线，允许沿经 PBF 有向拓扑证明的入口走廊进入六环主路；六环主路允许沿经证明的出口走廊回到界外。走廊即使有一部分几何位于六环内，仍按其来源、方向和终点判定，而不是按空间位置误判为受控普通道路。
16. 入口/出口走廊不得开放通往六环内普通道路、六环内其他高速或不属于该走廊的中途分叉。除明确属于 `R/H-T` 的主路部分外，走廊仍适用 camera.json、OSM access、单行线、道路关闭和 turn restriction；未记录的收费站设备不等同于已记录的禁行摄像头。
17. 非收费站的高速互通（如六环↔京津高速徐庄桥）允许生成 `R-H-T` 互转走廊：一端必须是六环主路 `R`，另一端必须是六环外通州允许高速 `H-T`；链由完整有向 link 链证明，按实际行驶方向分别生成 `R -> H-T` 与 `H-T -> R`。互转走廊即使部分几何位于六环内，仍按来源、方向和终点判定（与规则 15 同原则）；端点落在 `H-S/S-road/T-road/界外普通道路` 不生成走廊，链上存在收费节点时改走 `C-IN/C-OUT` 判定，链上非 `R/H-T` 主路边不豁免摄像头。
18. 通州北京省界（通州关系 `r2988902` 中 `admin_level=4` 的边界 way，即京冀/京津省界线）上的普通道路口，禁止作为 `CROSS_BOUNDARY_INBOUND` 的入界通行口：这些道路入京必然经过检查站，性质等同通州区内高速出口收费站，属于禁行对象；`OUTBOUND` 出京方向保持现状。六环主路、通州允许高速、收费站走廊 `C-IN/C-OUT`、`R-H-T` 互转走廊和高速检查站绕行辅路不受本条影响。
19. 全局禁止“普通道路无匝道直连高速主路”：非 `motorway_link` 且非高速主路的道路边，若直接与高速主路通过节点（主路在该节点双向通过）相连，禁止该普通边与任一主路边在该节点上的直接互转（转向级禁行，写入图内存 `TurnCostStorage`），普通道路自身保持可通行；即使普通边被收费站走廊包含也不豁免——走廊接入主路必须最终经 `motorway_link` 匝道；永乐/西集高速检查站绕行辅路按既有识别结果豁免。该规则经标准 A* 与自定义多目标 Dijkstra 共同的 `calcTurnWeight` 生效，覆盖环内普通路线（`INTERNAL_SAFE`/`EXTERNAL_ONLY`）与跨界 released/controlled 搜索，避免普通道路从小路直接并入高速主路，同时不会切断村庄等普通路网。

## 3. 地理对象

### 3.1 权威受控区域

设：

```text
S = 六环主路内侧闭环形成的 Polygon/MultiPolygon
T = 通州区行政区域 Polygon/MultiPolygon
U = valid(S union T)
B = boundary(U)
```

必须对两个面执行拓扑并集，再从结果面提取边界。不得对六环线和通州边界两条 LineString 直接做线合并。实现必须接受 `Polygon` 和 `MultiPolygon`，不能假设并集结果永远只有一个外环或没有孔洞。

边界数据使用 WGS84，并记录：

- 源京津冀 PBF 的 SHA-256；
- 六环内区来源和生成参数；
- 通州行政区 OSM relation `r2988902`；
- 通州北京省界线（通州关系 `admin_level=4` 边界 way 的并集，schema v4 起记录为 `provincial_border`）；
- 几何修复和并集工具版本；
- 生成时间、边界版本和人工批准状态。

六环部分以已验证的 G4501 双向主路中内侧闭环为权威边界，不再沿用旧算法“出界使用外侧环、入界使用内侧环”的双业务口径。边界不在服务启动时临时抓取或生成。候选文件在 `F:\CodexProjects\routing-plan\workspace` 下制作和审查，通过后才复制到 `F:\camera-safe-routing-data\boundaries` 作为运行输入。

### 3.2 内外判断与边界带

`U` 是唯一业务边界。为处理浮点误差和道路恰好沿界行驶，可从 `U` 派生很小的数值容差带，但容差带只服务几何稳定性，不能变成第二套业务边界。

- 点分类使用 `covers/contains` 明确边界点语义；
- 道路边使用完整几何判断穿越顺序，不能只比较首尾节点；
- 同一道路几何多次穿越边界时必须拆分或拒绝为不满足单调性的候选；
- 所有派生几何与路网 PBF 版本绑定。

## 4. 道路分类与禁行规则

### 4.1 OSM 与摄像头硬约束

以下规则优先于时间、距离、方向和连通性：

1. OSM `access`、单行线、不可通行状态和 turn restriction 对所有道路生效，高速主路不豁免这些路网约束。
2. 摄像头快照命中的适用道路有向 edge key 在搜索期禁止遍历。
3. QueryGraph 虚拟边继承基础边及其方向的摄像头禁行状态；只有明确属于六环主路 `R` 或六环外通州允许高速 `H-T` 的基础边不继承摄像头禁行。
4. 搜索成功后检查提取路径 edge key，并对适用道路几何执行独立摄像头零冲突校验。
5. 成功结果必须满足 `cameraConflictCount = 0`；该字段表示“适用摄像头规则的道路冲突数”，`R` 和 `H-T` 附近的摄像头不计为冲突。
6. 搜索超时或资源耗尽不能伪装成“无合规路线”，也不能放宽上述任一适用约束。

摄像头禁行必须同时满足“摄像头在作用域内”和“道路不是高速主路”：

```text
cameraInScope = camera 位于 U 内或边界上
                or distance(camera, B) <= 50 米

cameraExempt(edge) = edge 属于 R 或 H-T

cameraBlocks(camera, edge) = cameraInScope
                             and not cameraExempt(edge)
                             and distance(camera, edge) <= 50 米
```

两个 50 米参数含义不同：第一个是摄像头作用域的界外安全边距，第二个是摄像头点到道路几何的匹配和避让半径。最外侧实际受影响道路可能约到边界外 100 米。一个摄像头同时邻近豁免主路和适用道路时，只封锁适用道路或匝道；只匹配 `R/H-T` 时应记为“仅命中豁免边”，不能误报为未匹配。起终点检查、搜索期禁边、独立终检和前端限制点展示必须使用同一规则，不得出现搜索已豁免、终检仍拒绝的口径分裂。

```text
and 当前方向允许汽车通行
```

关系 ID 必须同时校验 `type=route`、`route=road`、`ref=G4501` 和 `wikidata=Q2562949`，不能只信任一个裸 ID。`ref=G4501` 和道路名称只用于审计，不作为关系缺失时的静默兜底；关系缺失、断裂或与标签不一致时，应拒绝发布该道路分类候选并要求人工复核。

路网缓存必须显式保留道路等级、link 标记及六环道路识别所需的信息。若 encoded values 或导入规则发生变化，必须使用新的候选 `graph-cache` 重建和回归，不能让旧缓存静默加载。

### 4.3 边界约束中的道路语义

路线状态与摄像头作用域是两套相关但不同的判断。边界产物必须同时保存 `controlled_area=U`、`sixth_ring_area=S` 和 `tongzhou_area=T`；仅保存 `U` 与 `T` 无法在六环和通州重叠区恢复 `S`，不得用 `U - T` 猜测。

| 类型 | 定义 | 摄像头规则 | 跨界通行规则 |
|---|---|---|---|
| `S-road` | 位于六环内区 `S`、且不属于已证明收费站有向走廊的普通道路和匝道 | 适用 | 普通道路可用于受控段；匝道不得用于上下高速或高速互转 |
| `R` | 经关系与路网标签确认的六环高速主路 | 完全豁免 | 允许主路通行；在 `S` 内不得驶入、驶出或切换其他高速 |
| `H-S` | 位于 `S` 的非六环高速主路 | 即使摄像头未命中也禁行 | 完全禁止遍历 |
| `T-road` | 位于 `T` 且位于 `S` 外的普通道路和匝道 | 适用 | 普通道路按受控道路处理；匝道仅允许无摄像头的 `H -> H` 高速互转 |
| `H-T` | 位于 `T` 且位于 `S` 外的非 link 高速主路，包括该区域内的六环主路 | 完全豁免 | 允许主路通行；可通过 `T` 内无摄像头匝道切换允许高速 |
| `O-road/H-O` | 位于并集面 `U` 外的普通道路、高速和匝道 | 超过边界外 50 米后不受摄像头约束 | 按 OSM 正常通行；界外路线只作参考 |
| `C-IN` | 从 `O-road` 沿实际可驾车方向经过入口收费节点并汇入指定方向 `R` 的完整有向 edge-key 链 | 除 `R` 部分外均适用 | 仅在路线已从普通道路合法释放到 `O` 后允许；不得从 `S-road` 中途进入 |
| `C-OUT` | 从指定方向 `R` 沿实际可驾车方向经过出口收费节点并最终到达 `O-road` 的完整有向 edge-key 链 | 除 `R` 部分外均适用 | 允许六环主路合法驶向界外；任何落入 `S-road/H-S` 的分叉拒绝 |
| `R-H-T` | 一端为指定方向 `R`、另一端为 `H-T` 的非收费站高速互通互转走廊，由完整有向 link 链证明 | 除 `R/H-T` 部分外均适用 | 仅允许 `R -> H-T` 或 `H-T -> R` 完整链；端点不得为 `H-S/S-road/T-road/界外普通道路`；中途分叉拒绝；链上无收费节点 |

收费站走廊是有向拓扑身份，不是新的道路等级，也不是摄像头豁免类型。构成走廊的道路可以是 `motorway_link`、`primary_link` 或经全量审计确认的其他可驾车道路；不能因 road class 不是 link 就自动排除，也不能把同一收费站附近所有道路并入走廊。`T` 内只有能够证明完整连接链为允许高速主路到允许高速主路、且链上无适用摄像头的匝道可以使用；不得由 `T-road` 进入高速，也不得由高速落到 `T-road`。

`R-H-T` 互转走廊与 `C-IN/C-OUT` 使用同一套拓扑验证原则，区别只在于锚点：收费站走廊以收费节点为必经证据，互转走廊以“另一端 `H-T` 主路”为终点证据。两者互斥：链上存在已映射收费节点时走 `C-IN/C-OUT` 判定，不生成互转走廊；互转走廊只在 `R` 与 `H-T` 之间生成，不能用于 `R -> H-S`、`R -> S-road/T-road` 或任何普通道路端点。链上非主路边继续适用 camera.json、OSM access、单行线、道路关闭和 turn restriction。

延庆城区现场标志限制暂不加入首版硬约束：它位于本方案并集边界外，且缺少可版本化的道路名单或几何。界外路线只作参考，最终由高德和现场标志负责；文档和界面不得把本地参考路线描述为完整法规保证。

## 5. 跨界道路状态机与边界通行口

有向通行口是一条可驾车道路遍历与 `B` 的真实交叉：

- `OUTBOUND`：从 `U` 内驶向 `U` 外；
- `INBOUND`：从 `U` 外驶向 `U` 内。

通行口保留基础 edge、directed edge key、边上比例、交点、方向和道路分类。相邻车道可以产生独立通行口；只有能证明同一有向道路拓扑的重复项才能合并。

收费站、高速出入口和 POI 不参与普通道路释放点生成，也不是强制途经点。收费站只用于证明释放后的参考路线是否可以通过某条有向入口/出口走廊连接六环指定方向主路。

纯几何“只允许穿越一次边界”不再适用，因为合法高速走廊可能在空间上出界后再次入界。跨界路线统一按以下方式校验：

1. `CROSS_BOUNDARY_OUTBOUND` 按原有向边顺序校验。
2. `CROSS_BOUNDARY_INBOUND` 先反转有向边顺序和方向，再按“界内端点到界外端点”校验。
3. 与界内端点相连的受控普通道路必须是唯一、连续的受控段。普通道路越过 `B` 到达 `O` 前处于 `CONTROLLED`；该阶段不得通过收费站走廊进入高速。
4. 普通道路第一次越过 `B` 进入 `O` 后进入 `RELEASED`。之后允许界外道路、允许高速主路、经证明的收费站有向走廊和经证明的 `R-H-T` 互转走廊，但不得进入不属于走廊的 `S-road/T-road`。
5. `RELEASED` 从 `O-road` 进入 `C-IN` 时进入 `ENTRY_PENDING`；只有沿完整有向链经过入口收费节点并抵达该走廊声明的六环主路方向才接受。中途落到 `S-road/H-S`、驶入错误主路方向或离开走廊均拒绝。
6. 六环主路进入 `C-OUT` 时进入 `EXIT_PENDING`；只有沿完整有向链经过出口收费节点并最终到达 `O-road` 才重新进入 `RELEASED`。中途落到 `S-road/H-S`、切换六环内其他高速或离开走廊均拒绝。
7. `H-S` 在任何状态下均禁止。`S` 内除 `C-IN/C-OUT` 和已验证 `R-H-T` 互转走廊外，不得通过匝道上下高速或切换高速；`T` 内仅允许无摄像头的允许高速互转匝道链。
8. `CROSS_BOUNDARY_INBOUND` 若继续复用规范方向校验，反转有向 edge trace 时必须同时交换 `C-IN/C-OUT` 的语义角色；不得只反转几何或 edge key 后沿用原标签。也可以直接按实际行驶方向实现入界状态机，但搜索期和终检必须选择同一种口径。
9. `RELEASED` 状态下 `R -> H-T` 互转走廊视同有向走廊块处理：从 `R` 进入链内 link 时校验链的精确有向 key 序列，中途落到 `S-road/H-S/T-road`、驶入错误方向或离开走廊均拒绝；到达 `H-T` 主路后恢复普通 RELEASED 通行。`H-T -> R` 方向同理，入界反转时 `R-H-T` 的两种方向角色互换。

按规范方向，典型合法序列为：

```text
S-road/T-road -> O-road
O-road -> C-IN -> R -> C-OUT -> O-road
O-road -> H-O -> R/H-T -> H-O/O-road
R -> C-OUT -> O-road
R -> R-H-T corridor -> H-T
H-T -> R-H-T corridor -> R
H-T -> camera-free T link chain -> R/H-T
```

典型非法序列为：

```text
S-road -> link -> R/H-S
S-road -> C-IN -> R
O-road -> C-IN -> S-road/H-S
R -> C-OUT -> S-road/H-S
R -> R-H-T corridor -> H-S/S-road/T-road
H-T -> R-H-T corridor -> S-road/T-road/H-S
R/H-T -> T link -> T-road
O-road/R/H-T -> S-road/T-road
```

因此业务本质不是禁止高速在几何上重入 `U`，而是禁止受控普通路段在释放后再次出现。状态约束必须同时在搜索期和最终有向 edge trace 校验中执行；JTS 只负责核对几何穿越位置，不能单独决定合法性。

物理 `boundaryCrossing` 仍保留给接口分段、地图标注和导航交接点。出界请求选择最终路线普通道路第一次合法释放产生的 `U -> U外` 交点；入界请求选择实际行驶方向最后一次从 `U外` 进入连续受控普通路段的交点。`C-IN/C-OUT` 和 `R-H-T` 互转走廊在几何上跨越 `B` 不产生新的控制释放点，也不能覆盖已经选定的普通道路交接语义。

## 6. 跨界候选与选择规则

### 6.1 控制释放点与受控侧距离

跨界业务候选从单纯的边界通行口升级为有向控制释放点 `r`：

- 普通道路释放点：任一允许的普通道路由 `S-road/T-road` 越过 `B` 进入 `O-road` 的位置；匝道只有位于 `O` 且满足正常 OSM 通行时才能作为界外参考段的一部分；
- 高速和收费站走廊不作为场景 3 的普通释放点；受控区内禁止从普通道路直接进入高速。路线先通过普通道路合法出界后，参考段才可以从 `O` 进入经证明的 `C-IN`，即使该入口链随后在空间上短暂回到 `U` 内。

对每个释放点 `r` 定义：

```text
出界：Dcontrolled(r) = 界内起点到 r 的合规道路距离
入界：Dcontrolled(r) = r 到界内终点的合规道路距离（按规范方向等价计算）
Dmin = min(Dcontrolled(r))
distanceTier = 1000 米
```

其中最小值按全部可达的合法普通道路释放点计算。距离采用真实道路长度，搜索仍同时执行摄像头禁边、OSM access、单行线、turn restriction、分区道路状态、超时和资源上限。

### 6.2 首选距离层

首选候选集为：

```text
C1 = { r | Dcontrolled(r) <= Dmin + 1000 米 }
```

这表示先把受控侧绕行限制在距最近合法出入界点 1 公里的范围内，降低因追求快速主干路而扩大受控行程、增加摄像头点位偏移风险的概率。

对 `C1` 中能够生成连续完整参考路线的候选，按以下顺序决胜：

1. 完整参考路线预计时间更短；
2. 完整参考路线距离更短；
3. `Dcontrolled` 更短；
4. 释放点 ID 稳定排序。

### 6.3 连通性扩展

`Dmin + 1000 米` 是首选层，不是提前宣布“无路”的硬上限。

如果 `C1` 中没有任何候选能生成满足全部硬约束、拓扑连续且形状合规的完整路线，则继续搜索下一距离层：

```text
C2: Dmin + 1000 至 Dmin + 2000 米
C3: Dmin + 2000 至 Dmin + 3000 米
...
```

在第一个出现完整合规路线的距离层停止扩展，并在该层及此前候选中按完整时间、完整距离决胜。只要首选层已经存在完整合规路线，就不为追求更短的界外参考时间继续扩大受控侧距离。

搜索完整耗尽仍无候选时才返回无合规路线；超时、线程中断、访问状态上限和队列资源限制分别返回资源错误。

### 6.4 与旧 180 秒规则的关系

- `Tmin + 180 秒` 从场景 3 业务选择、配置、日志和测试中删除；
- 场景 3 的首要候选门槛恢复为 `Dmin + 1000 米`，完整路线预计时间只在当前距离层内决胜；
- 场景 2 保持现有完整路线选择行为，不套用场景 3 的距离层候选规则。

## 7. 其他规划模式

### 7.1 两点都在受控区内

`INTERNAL_SAFE` 保持现有选择行为：在全部适用硬约束下按完整路线预计时间优先、完整距离其次，不套用场景 3 的距离层候选规则。

### 7.2 两点都在受控区外

`EXTERNAL_ONLY` 可继续返回本地完整参考路线，但前端和文档明确以高德导航为主。超过边界外 50 米的摄像头不参与禁行；OSM access、单行线和转向限制仍生效。本地路线不承诺与高德实时路况一致。

## 8. 导航交接点与附近地标

### 8.1 三类点不得混用

- `boundaryCrossing`：位于 `B` 上的技术交点，只用于路线分段和审计。
- `navigationHandoff`：用户可设为起点/终点并用于高德导航的严格界外点，类型为 `ORDINARY_ROAD` 或 `HIGHWAY`。
- `externalHandoff`：严格界外的兼容/审计字段，不作为用户可见导航锚点。

### 8.2 首版寻找规则

选定完整路线后，才沿实际道路轨迹寻找 `navigationHandoff`：

1. 从技术边界交点向界外方向扫描最终路线。
2. 沿路线累计距离不超过 500 米。
3. 候选坐标必须严格位于 `U` 外，不能使用无符号边界距离代替内外判断。
4. 候选必须是可操作普通道路点，排除高速主路、`motorway_link`、隧道、轮渡和道路类型不确定点。
5. 优先选择到 `B` 的最短直线距离达到 250 米的候选；满足者中选择沿路线最靠近边界的点。
6. 没有 250 米净空候选时，选择 500 米范围内净空最大的严格界外普通道路点。
7. 出界方向没有任何可靠普通道路点时返回 `navigationHandoff = null`，不得退回高速、技术边界点或界内点。
8. 仅入界方向在普通道路点为空时启动高速兜底：从技术交点沿最终参考路线向界外退回，优先约 300 米、最多 500 米。
9. 高速兜底必须位于最终路线的 `motorway` 主路几何上并严格处于 `U` 外；排除 link、隧道和轮渡。没有现成几何节点时允许在同一高速路段内插值。
10. 高速兜底不要求 250 米边界净空，`navigationHandoff.type = HIGHWAY`；普通道路交接点仍为 `ORDINARY_ROAD`。

“250 米净空”是候选点到边界的最短直线距离，不是沿路线行驶距离，也与候选距离层无关。

### 8.3 POI 和高德导航

高德导航链接继续使用 `navigationHandoff.gcj02` 精确坐标：

- 出界：`navigationHandoff -> 原始界外终点`；
- 入界：`原始界外起点 -> navigationHandoff`。

附近地标搜索半径不能固定为 200 米，而应根据实际边界净空动态限制：

```text
poiRadius = min(200 米, floor(clearance - 25 米))
```

普通道路点半径不足可靠阈值时回退到交接点逆地理编码。POI 候选仍优先收费站、高速出入口和互通；能够取得 POI 坐标时还要验证 POI 位于 `U` 外。复制操作复制高德可搜索的位置描述，不复制坐标文本。

高速交接点固定返回 `poiSearchRadiusMeters = 0`。前端不得搜索或替换为附近收费站/酒店等 POI，直接使用后端 GCJ-02 精确坐标打开高德导航，并显示路网道路名；道路名为空时显示“受控区外高速交接点”。

## 9. 实现方案（V2.3 / V2.4）

### 9.1 后端

V2.2 是可回归候选基线。V2.3 不改变边界、候选排序和接口，按以下职责增量实现；现有 `SixthRing` 类名和配置前缀暂为接口兼容保留：

1. 将边界候选格式升级为 schema v3，新增 `sixth_ring_area`；加载时验证 `S union T` 与 `controlled_area` 拓扑相等，并把三个面绑定同一 PBF 哈希。
2. 新增收费站源数据解析：从当前 PBF 提取 `barrier=toll_booth` 节点、相邻 way 和可用名称，再通过现有 `osm_way_id` 将源 way 与 GraphHopper 基础边对应。首先验证现有缓存是否足以完成稳定映射；只有确实需要新增 encoded value 时才切换独立 V2.3 graph-cache 冷构图。
3. 新增 `TollCorridorTopologyBuilder`：以收费节点为必经证据，沿真实 car access、单行线和转向限制分别求 `O -> toll -> R` 与 `R -> toll -> O` 有向链。拓扑搜索设置资源上限，但最终距离上限必须来自全量收费站审计的最大观测值与安全余量，不能用未经审计的固定距离静默丢站。
4. `RoadClassificationIndex` 增加 `C-IN/C-OUT` 的 directed edge key、收费站复合体 ID、连接的六环主路方向、来源 PBF/边界哈希和分类指纹；QueryGraph 虚拟边必须映射回原始有向基础边分类。
5. `BlockedEdgeGenerator` 继续使用 50 米匹配半径且只对 `R/H-T` 豁免；`C-IN/C-OUT` 中的非主路 edge 不豁免。新的走廊分类指纹进入路线/快照审计版本，避免旧拓扑静默复用。
6. 场景 3 的 `Dmin + n * 1000 米` 分层和层内完整时间优先保持不变；收费站不进入普通释放点候选集合。
7. 释放阶段只对白名单中的精确有向 `C-IN/C-OUT` edge key 放宽空间限制；普通界内道路和收费站复合体的其他分叉继续阻断。参考段从普通释放点的界外侧开始，确保入口走廊只能由 `O` 来源进入。
8. 搜索期约束与最终 edge trace 使用同一套走廊转换校验。若现有逐 edge 约束无法证明完整的 `O -> toll -> R` 或 `R -> toll -> O` 序列，必须升级为携带走廊状态的搜索，不能只靠终检删除违规结果。
9. `BoundaryCrossingResolver` 忽略收费站走廊自身的几何跨界，只认普通道路控制释放/进入；交接点继续从该交点沿最终路线向界外最多扫描 500 米。

不能通过给时间权重附加一个很小的距离系数来模拟严格二级排序，因为足够长的距离差仍可能反转时间优先级。多目标搜索应显式比较时间和距离，或采用能够证明等价的两阶段搜索。

### 9.4 V2.4 实现要点（`R-H-T` 互转走廊）

V2.3 是可回归候选基线。V2.4 不改变边界、候选排序、接口和收费站走廊，按以下职责增量实现：

2. 链的方向枚举与收费站走廊一致：同一互通按实际行驶方向分别生成 `R -> H-T` 与 `H-T -> R`，不能把复合体或匝道设成无方向白名单；共用短路段按 directed edge key 和后续终点分别判定。
3. `RoadClassificationIndex` 增加 `R-H-T` 的 directed edge key（`rhtExitEdgeKeys` 与 `rhtEntryEdgeKeys`）、另一端主路边、来源 PBF/边界哈希和分类指纹；QueryGraph 虚拟边必须映射回原始有向基础边分类。
4. RELEASED 搜索约束在 `C-IN/C-OUT` 判断之后增加 `R-H-T` 精确 key 放行；非链上的六环内匝道仍只放行收费站出口走廊 key。
5. 终检 `matchCorridorBlocks` 支持 `R-H-T` 角色：链前必须是 `R` 主路、链后必须是 `H-T` 主路（`H-T -> R` 方向相反），整链按精确 key 序列匹配后才标记为走廊块；`linkChainsAreValid` 对未命中走廊块的六环内 link 链保持拒绝。
6. 入界反转时 `R-H-T` 的 `EXIT/ENTRY` 角色随 `C-IN/C-OUT` 一起互换，不得沿用原标签。
7. `BlockedEdgeGenerator` 不变：`R-H-T` 链上非主路边不豁免摄像头，只有明确属于 `R/H-T` 的主路边保持豁免；分类指纹进入路线/快照审计版本。
8. `BoundaryCrossingResolver` 忽略 `R-H-T` 走廊自身的几何跨界，与 `C-IN/C-OUT` 同口径。
9. 启动日志和真实回归输出每条互转走廊的复合体 ID、方向、两端主路边、edge 数、长度、是否经过六环内 link 和分类版本；徐庄桥必须能被区分“未识别为合法互转走廊”和“参与时间比较后落选”。
