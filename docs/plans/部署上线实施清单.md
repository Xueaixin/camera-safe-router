## 0. 决策基线

- 构建机：Windows（现有 `F:\CodexProjects\routing-plan`，脚本保持 `.ps1`，随仓库迁移）。
- 服务器：Linux（腾讯云，4G 内存为主方案；2G 低配兜底模板见 5.3）。
- 系统：Alibaba Cloud Linux 4 LTS 或 Ubuntu 22.04/24.04（二选一，均兼容 JDK 21）。
- 数据根：Linux `/opt/camera-safe-routing-data`；Windows 构建机保持 `F:\camera-safe-routing-data`。路径一律通过 `-DROUTING_DATA_ROOT` 注入，代码不写死。
- 部署形态：首版裸机（JDK 21 + nginx + systemd）；Docker Compose 编排后置为学习项。
- CI：GitHub Actions 只负责构建并产出部署 artifact；部署步骤保持手动（国内服务器直连 GitHub 不稳定，见 7）。
- 域名 + Let's Encrypt 免费证书自动续期；https 上线后高德控制台白名单加 https 域名，浏览器定位才可用。
- 本方案（MMAP_STORE，2G 低配优先）：分支 `jingjinji-MMAP`，缓存目录 `graph-cache/jingjinji-compliant-time-v2-mmap`，边界 `boundaries/sixth-ring-boundary-jingjinji.geojson`；RAM 对应分支 `jingjinji-RAM`（缓存 `...-v2`）。

## 1. 服务器资源

| 项 | 4G 主方案 | 2G 低配兜底 |
|---|---|---|
| 存储类型 | RAM_STORE（默认） | MMAP_STORE + 4G swapfile（必须） |
| 内存 | 4G | 2G + 4G swapfile（必须） |
| JVM | `-Xmx2048m` | `-Xmx1280m`（可试 `1536m`）|
| 元空间 | 默认 | `-XX:MaxMetaspaceSize=256m` |
| 并行候选评估 | 开启（默认） | `parallelCandidateEvaluation=false` |
| 候选评估线程 | 4 | 2 |
| 快照/备份保留 | 默认 | 调低 `snapshotRetentionCount`、`backupRetentionCount`、`failedRetentionCount` |
| 预期 | 启动约 2 分钟，查询正常 | 启动约 1.5~2 分钟，查询基本同水平，长期 swap 有磨损 |
| 结论 | 推荐 | 可行（MMAP 已实测），真 2G 物理机器上线前仍需实测换页行为 |

说明：RAM 实测 java 进程约 2.3GB 私有内存（`-Xmx2048m`）；MMAP 实测约 1.5GB（`-Xmx2048m` 与 `-Xmx1280m` 低配均约 1.5GB），降幅约 1/3。CPU 2 核对启动阶段（分类/收费站走廊/互转走廊）和跨界搜索影响明显。

## 2.5 图缓存存储类型与目录

- **RAM_STORE（默认）**：图数据全部读入 JVM 堆，启动后常驻内存，访问最快；缓存目录 `graph-cache/jingjinji-compliant-time-v2`。适合 4G 及以上。
- **MMAP_STORE（2G 低配）**：图数据以内存映射文件方式加载，按需换页，进程常驻内存显著下降；缓存目录 `graph-cache/jingjinji-compliant-time-v2-mmap`。适合 2G。
- **两存储不兼容**：RAM 与 MMAP 构建的缓存不能混用，切换存储类型必须重新构图（`graph-build`），缓存目录必须区分。
- **开关**：构图与启动均需 `-Drouting.graph.storage=MMAP`（JVM 系统属性，systemd 模板已带）；`application.yml` 默认 `candidate-graph-cache-path` 已指向 `-v2-mmap`，不指定存储属性时使用默认 RAM_STORE（本分支必须带 MMAP）。
- **寻路时长（实测，预热后）**：MMAP 与 RAM 基本同水平（毫秒级；朱辛庄↔武清 149.9km 跨界约 0.4~0.6s，低配约 0.6~1.5s）；路线结果与 RAM 完全一致。
- **启动速度**：MMAP 与 RAM 就绪时间基本持平（约 1.5~2 分钟），启动耗时主要来自分类/走廊/索引构建，MMAP 无明显优势。
- **注意**：本机实验内存充足，页缓存不受限；真实 2G 物理内存下跨界长查询的换页行为需在真机上验证。

## 2. 域名、证书与高德白名单

1. 购买域名（确认首年 10 元为促销价，续费价格需提前确认），DNS 增加 A 记录指向服务器 IP。
2. 安全组放行 80/443（验证与 https），22 仅对可信来源开放。
3. 安装 certbot，签发 Let's Encrypt 证书（HTTP-01 验证），配置自动续期（certbot 自带 timer）。
4. nginx 配置：443 + http 跳 https。
5. 高德开放平台控制台：JS API 安全密钥 + 域名白名单加入 `https://<正式域名>`；上线前验证地图加载、POI 搜索、定位。

## 3. 构建机出包（复用现有脚本，不新增）

数据包（仅在 PBF 月度更新时变化）：

```powershell
.\scripts\build-deployment-package.ps1 -Pbf 'F:\camera-safe-routing-data\osm\jingjinji-latest.osm.pbf' -CameraJson 'F:\camera-safe-routing-data\cameras\camera.json' -OutDir <输出目录>
```

产出 `data.zip`（osm/boundaries/graph-cache/cameras，约 500MB，MMAP 缓存）+ `server.jar`。本分支 `build-deployment-package.ps1` 已默认以 `-Drouting.graph.storage=MMAP` 构图。

MMAP 方案构图（2G 低配，构建机）：

```powershell
java -Drouting.graph.storage=MMAP -jar server.jar graph-build --pbf <pbf> --cache-out <graph-cache\jingjinji-compliant-time-v2-mmap>
```

RAM 方案构图不加 `-Drouting.graph.storage`。两存储缓存不兼容，目录必须区分（`...-v2` 与 `...-v2-mmap`）。

代码包（每次代码更新时构建）：

```powershell
# 后端
mvn -DskipTests package   # server/target/camera-safe-routing-server-0.1.0-SNAPSHOT.jar
# 前端（构建机本地 .env.local 提供高德 key，不进 git）
cd web && npm ci && npm run build   # 产出 web/dist
```

上传到服务器：`data.zip`、`server.jar`、`web/dist`。

## 4. Linux 服务器新增内容（bash 体系，替换现有 PowerShell 入口）

### 4.1 新增脚本（`deploy/linux/` 或 `scripts/linux/`，随仓库提交）

- `init.sh`：创建运行用户 `routing`；建 `/opt/camera-safe-routing-data` 子目录（osm/boundaries/graph-cache/cameras/snapshots/logs/downloads/backups）；属主设为 `routing`；2G 低配时创建 4G swapfile。
- `deploy.sh`：解压 `data.zip` 到数据根（先校验包内哈希）→ 放置 `server.jar` → 放置前端 dist 到 nginx 目录 → 重启 systemd 服务 → 轮询 readiness。
- `update-routing-data.sh`：月度更新——备份当前 osm/boundaries/graph-cache → 校验新包 → 解压替换 → 重启 → readiness + 关键路线验证；支持 `--rollback` 还原。
- `camera-safe-routing.service`（systemd unit 模板）：见 4.2。
- nginx 站点配置模板（`/etc/nginx/conf.d/camera-safe-routing.conf`）：见 4.3。

服务器只装：JDK 21（temurin/openjdk）、nginx、（2G 兜底需 `swap`/`unzip`）。不装 osmium、Maven、Node。

### 4.2 systemd 模板（4G 主方案示例）

```ini
[Unit]
Description=Camera Safe Routing Server
After=network.target

[Service]
User=routing
WorkingDirectory=/opt/camera-safe-routing
Environment=ROUTING_DATA_ROOT=/opt/camera-safe-routing-data
Environment=SERVER_PORT=8080
  Environment=CAMERA_UPDATE_ENABLED=true
  ExecStart=/usr/bin/java -Xmx2048m \
    -Drouting.graph.storage=MMAP \
    -Dapp.sixth-ring.boundary-path=/opt/camera-safe-routing-data/boundaries/sixth-ring-boundary-jingjinji.geojson \
    -Dapp.sixth-ring.require-approved-boundary=true \
    -jar /opt/camera-safe-routing/server.jar
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

2G 低配模板差异：`-Xmx1280m -XX:MaxMetaspaceSize=256m`、`-Dapp.sixth-ring.parallel-candidate-evaluation=false`、`-Dapp.sixth-ring.candidate-evaluation-threads=2`。`candidate-graph-cache-path` 已由 `application.yml` 默认指向 `...-v2-mmap`。

### 4.3 nginx 配置模板

```nginx
server {
    listen 80;
    server_name <正式域名>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name <正式域名>;
    ssl_certificate     /etc/letsencrypt/live/<正式域名>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<正式域名>/privkey.pem;

    root /var/www/camera-safe-routing;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 5. 实施步骤（首次上线顺序）

1. 服务器：购买、装系统、开安全组（80/443/22）。
2. 域名解析 + certbot 签发证书（第 2 节）。
3. 服务器初始化：建用户/目录/swap（4.1 `init.sh`），装 JDK 21 + nginx。
4. 构建机：出 `data.zip` + `server.jar` + `web/dist`（第 3 节），上传服务器。
5. 服务器：`deploy.sh` 部署 + systemd 启动 + nginx 配置重载。
6. 高德控制台白名单加 https 域名。
7. 验证（第 6 节）。

## 6. 上线验证清单

- `GET /api/v1/readiness` 返回 `READY`，日志确认边界版本、省界排除 78、非法直连转向写入数；GraphHopper 启动日志中的存储类型（`RAM_STORE`/`MMAP_STORE`）与缓存目录配套。
- 固定路线抽样回归：东/南/西/北出环入环各 1、朱辛庄↔武清、西小营↔防汛路43、河西务→天祥（省界规则）。
- 摄像头：快照版本、受控摄像头数、禁行边数符合预期；手动 admin 接口可触发更新/重建快照。
- 前端：https 打开、地图加载、POI 搜索、设置起终点、规划路线、完整行程/环内行程视图。
- 定位：移动端 https 下授权并显示当前位置。
- 日志写入 `/opt/camera-safe-routing-data/logs`，中文无乱码（文件 UTF-8）。

## 7. CI（后置，暂不实施）

- GitHub Actions：push dev/main → JDK21 + Node 构建 jar + dist（AMAP 变量从 repository secrets 注入）→ 测试 → `upload-artifact` 产出部署包。
- 部署步骤保持手动：从 GitHub 下载 artifact → 连同 data.zip 上传服务器 → 执行 `deploy.sh`。
- 不采用 gitee CI（不免费）；不做“CI 自动 SSH 部署到服务器”（国内网络不稳）。
- 仓库已在 GitHub（origin），无需迁移；`web/.env.local` 继续不进 git。

## 8. 待确认/风险项

- 2G 低配（MMAP）已在本机实测：内存约 1.5GB、寻路毫秒~1.5s、路线结果与 RAM 一致；上线前仍需在真实 2G 物理机器实测启动、摄像头更新与跨界查询的换页行为。

- Docker Compose 编排为后置学习项，不阻塞首版裸机上线。
