## 3. 摄像头自动化剩余工作

剩余开发任务：

1. 增加人工选择备份版本的回滚入口，复用候选校验和原子发布流程。
2. 接入连续失败监控告警。

生产环境的数据源许可确认、定时运行观察、阈值确认和摄像头坐标控制点核验由使用方执行，不计入后续编码任务。摄像头源仍按原始字节 SHA-256 比较；数组顺序、字段顺序或排版发生变化时视为新版本并重新构建快照，不增加业务内容指纹。

完成定义：远程失败或坏数据不能污染当前文件；服务持续使用上一有效快照；报告明确原始条数、过滤条数、匹配数和版本哈希。

V2.2 已实现并完成候选真实数据回归，但 2026-08-10 的收费站方向案例证明其不能进入生产批准：

- 六环主路和六环外通州区域内的高速主路完全豁免摄像头；六环内其他高速主路永久禁行，OSM access、单行线、道路封闭状态和 turn restriction 始终生效。
- 高速匝道不享有摄像头豁免。V2.2 六环内普通道路不得上下高速或经匝道切换高速，仅识别六环主路最终通往界外的收费站连接方向。
- 六环外通州区域内只允许无适用摄像头的 `H -> 匝道链 -> H` 高速互转，不允许高速落到受控普通道路。
- 跨界路线统一按“界内端点到界外端点”校验；实际入界请求反转有向边序列后执行同一状态机。
- 与界内端点相连的受控普通路段必须唯一且连续；普通道路释放后不得再进入受控普通道路。
- 六环主路和六环外通州高速主路可以因走廊几何出界再入界，但不能借此下到受控区普通道路。
- `Dcontrolled` 截止于普通道路释放点；受控区高速不再作为普通控制释放点。
- 控制释放点只用于内部搜索；接口继续返回最终路线的物理 `boundaryCrossing` 和严格界外 `navigationHandoff`。

### 4.1 跨区域路线算法备注

北京、天津、河北已经能够使用同一份路网稳定规划并继续硬避开摄像头。源码已接入六环内侧与通州并集边界策略，但新的边界候选和 V2 缓存尚未切换到运行目录。

当前冻结规则不强制使用六环高速、收费站或高速出入口。跨界模式先把受控侧合规道路距离限制在 `Dmin + 1000 米` 的首个可行层，再按完整路线时间和距离选择大方向。六环主路和六环外通州高速主路属于摄像头豁免走廊；普通道路释放到界外后，还可以沿经 PBF 证明的收费站有向入口走廊上六环，再沿有向出口走廊回到界外。收费站走廊本身不豁免摄像头，也不能开放通往受控普通道路的分叉。端点均在界内的场景保持现有完整时间优先行为。

## 7. 发布阻断条件

出现任一情况不得称为可发布：

- 成功路线的 `cameraConflictCount` 非零。
- 禁行没有发生在 GraphHopper 搜索期间。
- QueryGraph 可以绕过禁行基础边。
- 六环或通州高速主路仍因摄像头进入禁行位图，或者普通道路/匝道错误继承高速豁免。
- 跨界路线在控制释放后能够进入受控普通道路，或者合法高速跨界因纯几何重入被拒绝。
- 合法的 `O -> 收费站入口走廊 -> 六环指定方向主路` 因走廊位于界内或 road class 不是 `motorway_link` 被拒绝，或者收费站走廊使界内普通道路/错误方向分叉获得通行。
- 收费站入口/出口未按 directed edge key、单行线、收费节点和目标主路方向分别证明，或者大觉寺未参与合法完整路线比较却静默选择军庄。
- 合法的 `R -> H-T` / `H-T -> R` 互转走廊因匝道几何与六环内区相交被拒绝（如徐庄桥），或互转走廊使 `H-S/S-road/T-road` 端点、中途分叉或含收费节点链获得通行。
- PBF 与缓存哈希不一致。
- `COMPLIANT_TIME_V2` 缓存缺少道路身份编码，或启动道路分类审计失败。
- 并集边界未按正式化流程发布，或真实 PBF 固定路线与性能回归未通过。
- 新摄像头数据未经校验或更新失败时覆盖旧快照。
- 前端直接把 WGS84 定位绘制到高德地图。
- 手动重新规划失败后清空旧路线。
- 真实 Key、证书、PBF、缓存或快照进入 Git。
- 未执行的 IDE、构建或手机验证被描述为已经通过。
- 未审批的保留通行口被静默视为生产可用。
