# 六环边界路线规划算法方案

状态：历史基线，已由《六环与通州并集边界路线规划方案》替代；以下实现和 14 条真实回归仅代表 2026-08-06 的旧边界与 `COMPLIANT_DISTANCE_V1`
更新时间：2026-08-06

## 1. 目标

本系统是高德导航的辅助系统，核心职责是在当前摄像头禁行快照下，为六环内受控路段找到距离最短的可连通路线，并提供可供用户判断大方向的完整参考路线。

本方案中的核心地理对象是“六环边界”和“有向边界通行口”。六环高速、收费站和高速出入口都不是强制途经点，也不参与核心候选生成。路线可以通过普通道路、匝道或高速跨越六环边界。

## 2. 不变量

以下约束优先于任何距离、时间或道路偏好：

1. 当前摄像头快照命中的有向 edge key 必须在 GraphHopper 搜索阶段返回无穷权重。
2. QueryGraph 虚拟边必须继承对应基础边和方向的禁行状态。
3. 后端返回成功前必须检查提取路径的 edge key，并使用 JTS 对完整返回几何执行独立零冲突校验。
4. 成功响应必须满足 `cameraConflictCount = 0`，不得返回已知违规的降级路线。
5. 道路访问权限和 OSM 转向限制属于交通合法性硬约束。
6. 搜索超时或访问节点超限不等于无路，不能映射为 `NO_COMPLIANT_ROUTE`。
7. `INTERNAL_SAFE` 只由起终点位置分类，完整路线可以出环再入环，不施加六环空间限制。
8. `CROSS_BOUNDARY_OUTBOUND` 穿过外边界后不得重新进入六环内核；`CROSS_BOUNDARY_INBOUND` 穿过内边界后不得再次离开六环内核。
9. 上述单调性必须同时在搜索期限制道路遍历，并在候选拼接后用独立几何校验确认，不能只做结果过滤。
10. `boundaryCrossing` 只证明路线几何穿过边界；参考段必须从已选通行口的真实道路拓扑继续搜索，不能按同一平面坐标跳到桥上、桥下或六环高速。
11. 只有能够按实际路线拓扑证明位于普通道路上的点才能作为用户导航端点；入环路线在边界处仍为高速或匝道时，应使用驶离高速后安全段中的首个普通道路点。无法证明时必须隐藏端点操作，不能用高速主线或技术边界点降级。

## 3. 术语

### 3.1 六环边界

用于判断点位位于六环内或六环外的闭合 WGS84 几何。边界应由明确来源生成、人工抽查并版本化，不能随路网更新静默变化。

### 3.2 有向边界通行口

一条允许汽车通行、其几何从六环边界一侧跨到另一侧的有向道路遍历：

- `OUTBOUND`：从六环内驶向六环外。
- `INBOUND`：从六环外驶向六环内。

同一基础边可以只支持一个方向。相邻车道、双线道路和同一匝道产生的重复遍历需要聚合，但聚合不能丢失方向和道路拓扑。

### 3.3 环内合规距离

跨界路线中，六环内点与有向边界通行口之间，在摄像头、道路权限和转向限制硬约束下的最短道路距离。

### 3.4 完整参考路线

由本地京津冀路网生成、连接原始起终点的完整几何，用于选择大方向和向用户提供参考。实际六环及环外导航以高德为准，但后端返回的完整几何仍不得违反当前摄像头硬约束。

### 3.5 导航交接点

`navigationHandoff` 是从拓扑连续路线中选出的普通道路可选点。选择同时使用参考段和安全段的 `road_class`、`road_class_link`、`road_environment` 轨迹，并限制在技术边界前后 1 公里的路线范围内：

- 普通跨界路线从环外参考段选择可操作道路点。
- 入环路线在技术边界处仍行驶于高速主线或连接匝道时，从安全段沿行驶方向继续识别 `motorway/link -> 普通道路` 的真实拓扑转换，选择转换后的首个普通道路点；该点可以位于外边界内侧。
- 高速主线、连接匝道、隧道、轮渡和无法证明道路类型的点均不返回；不得使用 `boundaryCrossing` 兜底。

它非空时作为 `safeSegment` 与 `referenceSegment` 的拼接点，并允许前端提供“设为起点/终点”、附近交通地标和精确高德导航；为空时不暴露这些操作。用户可见位置必须锚定该点，不能改用仅满足空间审计条件但可能沿路线相距很远的 `externalHandoff`。

### 3.6 环外审计位置

`externalHandoff` 是从最终参考段上选出的、严格位于六环外边界之外的位置。它不是通行口，不改变路线选择；路线长时间沿边界带行驶时，它可能远离道路安全导航交接点。后端继续返回该点的双坐标、边界净空和最大 200 米的严格环外搜索半径，用于审计与旧客户端兼容；当前前端不再用它解析用户可见位置。

### 3.7 用户地标与高德导航

交接点弹窗以 `navigationHandoff.gcj02` 为唯一坐标锚点，在 200 米内解析附近 POI。候选按业务可识别性排序：收费站、高速出入口和互通最高，其他交通设施、路口、桥梁和立交次之，再按距离选择普通 POI；没有合适候选时使用交接点的逆地理编码地址。展示与复制文案不附加未经证明的“六环外侧”。

“复制地标”只复制移动端高德可搜索的文本。“高德导航”不依赖文本搜索，直接以 GCJ-02 坐标构造导航链接：出环为 `navigationHandoff -> 原始环外终点`，入环为 `原始环外起点 -> navigationHandoff`。

## 4. 场景和行为

| 起点 | 终点 | 规划模式 | 行为 |
|---|---|---|---|
| 六环外 | 六环外 | `EXTERNAL_ONLY` | 当前接口返回本地完整参考路线；前端自动切换高德导航的产品交互尚未实现 |
| 六环内 | 六环内 | `INTERNAL_SAFE` | 返回全局距离最短的合规路线，必要时允许出环再入环 |
| 六环内 | 六环外 | `CROSS_BOUNDARY_OUTBOUND` | 优先尽快出六环，再比较不重返内核的完整参考路线 |
| 六环外 | 六环内 | `CROSS_BOUNDARY_INBOUND` | 尽可能晚进入六环，再比较入环后不离开内核的完整参考路线 |

边界 POC 当前建议把内外两条六环车行环线之间定义为边界带：出环以穿过外侧环线为准，入环以穿过内侧环线为准。这样不会把“到达六环线”误判成“已经出环”，也不会把尚未真正进入环内的边界带计入入环后的受控距离。起点或终点落在边界带时的归类规则仍需结合道路宽度、匝道和定位误差人工确认。

## 5. 路线选择规则

### 5.1 环内到环内

在全部摄像头和交通合法性硬约束下按道路距离求全局最短路径。端点都位于六环内不代表路线必须留在环内；当东、西两端贴近六环时，出环利用六环道路再入环可以成为合法最优解。

### 5.2 环内到环外

令 `Pout` 为全部方向正确且可参与搜索的 `OUTBOUND` 通行口。对每个 `p`：

1. 计算起点到 `p` 的最短环内合规距离 `Dinside(p)`。
2. 丢弃不可达通行口。
3. 令 `Dmin = min(Dinside(p))`。
4. 建立候选集 `C = { p | Dinside(p) <= Dmin + 1000 米 }`。
5. 对 `C` 中每个通行口计算经过该通行口到原始终点的完整参考路线。
6. 在候选集中按完整参考路线距离选择最优方案，预计时间只作为稳定的次级决胜条件。

这保证系统优先尽快出六环，同时允许最多 1 公里的环内距离差来选择大方向明显更合理的完整路线。

### 5.3 环外到环内

令 `Pin` 为全部方向正确且可参与搜索的 `INBOUND` 通行口。对每个 `p`：

1. 计算 `p` 到终点的最短环内合规距离 `Dinside(p)`。
2. 丢弃不可达通行口。
3. 令 `Dmin = min(Dinside(p))`。
4. 建立候选集 `C = { p | Dinside(p) <= Dmin + 1000 米 }`。
5. 对 `C` 中每个通行口计算原始起点经过该通行口到终点的完整参考路线。
6. 在候选集中按完整参考路线距离选择最优方案，预计时间只作为稳定的次级决胜条件。

这等价于尽可能晚进入六环，并最小化进入六环后的受控路段距离。

### 5.4 跨界单调约束

端点分类和路径形状是两件事。跨界候选的两个分段使用不同空间硬约束：

- 出环安全段只能遍历外边界覆盖范围内的道路；到达外边界上的通行口后，参考段允许使用边界带和六环道路，但不得进入内边界以内。
- 入环参考段在到达内边界通行口之前不得进入内边界以内；通行口至终点的安全段只能遍历内边界覆盖范围内的道路。
- 通行口位于跨界道路内部时，多目标搜索允许遍历该 edge 到通行口的前缀，但禁止继续遍历越过边界的剩余部分。
- 拼接候选后，`SixthRingRouteShapeValidator` 使用 JTS 再次检查安全段覆盖关系和参考段不进入内核；失败候选不参与完整路线决胜。

这里刻意允许参考段重新进入“边界带”，因为六环道路和互通匝道可能位于边界带内；禁止的是重新进入内边界包围的核心区域。

搜索期空间判断使用 JTS `PreparedGeometry` 加速。基础图 edge 的判定结果以位图按 edge ID 缓存；`QueryGraph` 虚拟 edge 的 ID 会在不同请求间复用但几何取决于吸附点，因此不得按虚拟 edge ID 复用缓存。本实现只缓存稳定的基础图 edge，虚拟 edge 每次按实际几何判断。

### 5.5 不能使用简单加权

不得使用 `环内距离 * A + 环外距离 * B` 直接决定通行口。简单加权可能为了大幅缩短环外路段而接受明显更长的环内路线，破坏“优先出六环”的主目标。候选容差必须使用固定的 1000 米绝对值。

## 6. 六环边界数据

### 6.1 建议产物

仓库保存一份经过验证的小型 GeoJSON，并记录：

- 来源 PBF SHA-256 和 OSM 数据时间。
- 生成工具、命令和人工修订记录。
- WGS84 坐标系声明。
- 几何闭合性、有效性和覆盖范围。
- 东、南、西、北控制点。

PBF 和生成过程中的大文件仍保存在外部数据目录，不提交 Git。

### 6.2 更新原则

六环边界是业务分类基准，不随每次 PBF 更新自动替换。新候选边界必须生成差异报告并人工批准。GraphHopper edge ID 会随图重建变化，因此有向通行口应在当前图加载后根据版本化边界重新提取。

## 7. 有向通行口提取 POC

POC 至少验证：

1. 可驾车基础边几何与边界真实相交，而不是只比较节点包围盒。
2. 通过相交点两侧的位置判断 `OUTBOUND` 或 `INBOUND`。
3. 单向道路只生成允许的遍历方向。
4. 道路沿边界行驶、重复穿越、匝道、多车道和几何抖动不会产生大量伪通行口。
5. 聚合后的通行口能够保留用于路径重建的 edge key、方向和边界交点。
6. 东、南、西、北四个方向都有人工地图抽查样本。

当前生产拓扑构建器已经处理边内部交叉、边端状态转换、单边重叠退出和多边边界链。边界节点状态必须从来源侧可达边进入，沿边界传播和驶向目标侧前均检查单向访问及 turn costs；相同有向 edge key 和边上比例会去重，平行车道保持独立。

真实图生成 714 条候选，已直接通过单点正向/反向多目标搜索和摄像头零冲突校验。算法已经接入正式路线接口；人工地图抽查和边界带规则尚未批准，因此边界文件仍以开发候选状态加载，生产环境可通过 `SIXTH_RING_REQUIRE_APPROVED_BOUNDARY=true` 拒绝未批准边界。

## 8. 搜索算法方向

### 8.1 环内多目标最短路

逐个通行口运行完整双向 A* 可能造成不可控的总耗时。优先验证在同一个 QueryGraph 和禁行快照下执行一次单源多目标最短路：

- 环内到环外：从环内起点正向搜索所有 `OUTBOUND` 通行口。
- 环外到环内：从环内终点反向搜索所有 `INBOUND` 通行口，并按正向道路合法性重建路线。

只有进入 `Dmin + 1000 米` 候选集的通行口才继续运行完整参考路线搜索。

配置 POC 已证明 GraphHopper 11 的 `DijkstraOneToMany` 不能直接复用：node-based 模式拒绝带 turn costs 的权重，且单节点状态无法区分不同到达 edge key 的转向合法性。搜索 POC 使用自建 edge-based 多目标 Dijkstra；首个通行口确定 `Dmin` 后继续到队列最小距离超过 `Dmin + 1000 米`。反向搜索必须按正向驾驶顺序计算反转后的转向代价。

### 8.2 完整性和资源限制

只有搜索完整耗尽可达图后仍找不到通行口，才能证明无合规路线。超时、线程中断、队列拒绝和访问节点上限必须使用独立错误状态，并保留重试或提高预算的可能。

## 9. 当前算法需要先修正的基础

以下基础项已经完成：

1. `COMPLIANT_DISTANCE_V1` 默认 Profile 启用 turn costs，真实京津冀图导入 2,359 条可用 OSM 转向限制。
2. `road_access` 对 private、destination、customers、delivery、agricultural、forestry 使用入口高代价，允许受限道路作为起终点但避免普通穿行；`NO` 为硬不可达。
3. 基础路线使用每公里 1,000,000 秒的距离主导权重，路线时长仍按道路速度单独计算；生产多目标搜索复用同一合法性规则并按真实米数累计 Dmin。
4. 新权重继续被 `BlockedEdgeWeighting` 包装，搜索期禁边、QueryGraph 方向继承、提取路径 edge key 检查和 JTS 终检均已回归。
5. 最大访问状态属于资源上限，映射为 503 `ROUTE_SEARCH_RESOURCE_LIMIT`；搜索或外层请求超时映射为 503 `ROUTE_SEARCH_TIMEOUT`，均不再误报 `NO_COMPLIANT_ROUTE`。

## 10. 接口契约

OpenAPI 1.3 已在正式路线接口实现，请求仍只提交起点、终点和车型，规划模式与通行口均由服务端自动选择：

- `planningMode` 为 `INTERNAL_SAFE`、`CROSS_BOUNDARY_OUTBOUND`、`CROSS_BOUNDARY_INBOUND` 或 `EXTERNAL_ONLY`。
- `boundaryVersion` 记录本次内外分类和通行口提取使用的边界版本。
- `boundaryDirection` 和 `boundaryCrossing` 只在跨界模式非空。
- `boundaryCrossing` 返回不透明 `portalId`、道路名称、边界角色以及 WGS84/GCJ-02 双坐标；它是技术审计点，不是导航端点，也不向客户端暴露会随构图变化的 GraphHopper edge key。
- `navigationHandoff` 仅在技术边界前后 1 公里路线范围内能够证明存在普通道路点时非空，返回双坐标、到外边界的无符号净空和可空道路名；入环高速场景可取安全段中的真实驶离点，高速、匝道或不确定点本身必须为空。
- `externalHandoff` 只在跨界模式非空，返回严格位于外边界之外的双坐标、边界净空和兼容搜索半径；当前前端只把它视为审计/兼容字段。
- `safeSegment` 和 `referenceSegment` 均包含距离、时长和可独立绘制的几何；`navigationHandoff` 非空时两段在该点拼接，否则在 `boundaryCrossing` 拼接。
- 原有 `geometry`、`distanceMeters` 和 `durationSeconds` 保留为完整参考路线，避免客户端必须自行拼接路段。
- 摄像头快照、禁行边版本和 `cameraConflictCount=0` 不变。

四种模式的非空规则如下：

| 模式 | 通行方向/通行口 | navigationHandoff | externalHandoff | safeSegment | referenceSegment | 完整 geometry |
|---|---|---|---|---|---|---|
| `INTERNAL_SAFE` | 空 | 空 | 空 | 完整合规路线 | 空 | 有 |
| `CROSS_BOUNDARY_OUTBOUND` | `OUTBOUND`/非空 | 可空 | 非空 | 起点至导航交接点或技术边界点 | 拼接点至终点 | 有 |
| `CROSS_BOUNDARY_INBOUND` | `INBOUND`/非空 | 可空 | 非空 | 拼接点至终点 | 起点至导航交接点或技术边界点 | 有 |
| `EXTERNAL_ONLY` | 空 | 空 | 空 | 空 | 完整环外参考路线 | 有 |

`EXTERNAL_ONLY` 继续由现有路线接口承载并返回完整参考几何，不增加独立分类接口。当前前端仍绘制该 `geometry`；提示或切换外部导航属于尚未完成的产品交互，不能描述为已经接入高德路线规划。

跨界前端默认绘制完整 `geometry`。只有 `navigationHandoff` 非空时才显示交接点标记和“设为终点/设为起点”，操作进入 `safeSegment` 视图；同一弹窗围绕该点解析并复制附近交通地标，并提供使用精确 GCJ-02 坐标的高德导航。

## 11. 错误语义

| 场景 | 结果 |
|---|---|
| 完整搜索证明环内点无法到达任何方向正确的通行口 | `NO_COMPLIANT_ROUTE` |
| 起点或终点位于当前摄像头限制区 | 保留现有起终点限制错误 |
| 搜索超时 | `ROUTE_SEARCH_TIMEOUT`，不得映射为无路 |
| 访问节点达到上限 | `ROUTE_SEARCH_RESOURCE_LIMIT`，不得映射为无路 |
| 边界或通行口数据未就绪 | `SIXTH_RING_TOPOLOGY_NOT_READY` |
| 最短候选可达但完整参考段失败 | `REFERENCE_ROUTE_FAILED`，不得谎报环内无路 |

## 12. 验证矩阵

### 12.1 合成图

- 环内到环内的距离最短路线。
- 环内到环内允许全局最短路线出环后再入环。
- 环内到环外优先最短出环。
- 环外到环内最小化入环后距离。
- 出环参考段重返内核时必须在搜索期被阻断并被独立形状校验拒绝。
- 入环安全段再次离开内核时必须在搜索期被阻断并被独立形状校验拒绝。
- 两个通行口相差 999 米时由完整路线决胜。
- 两个通行口相差 1001 米时不得改选更远通行口。
- 最近通行口被摄像头阻断后选择其他通行口。
- 全部通行口被阻断后返回无路。
- 搜索被截断时不返回无路。
