# 运行配置与数据目录

## 1. 目标

运行数据必须与 Git 仓库和 IDE 工作目录解耦。换电脑、换克隆目录或从 IDEA/命令行启动时，不应依赖 `F:\CodexProjects\routing-plan` 之类的机器绝对路径，也不应依赖 `../../data` 这种工作目录敏感路径。

普通开发只需要统一数据根目录；PBF、摄像头、缓存和快照从该目录派生。

## 2. 标准目录

Windows 默认根目录为后端启动所在盘的：

```text
\camera-safe-routing-data
```

例如 `server` 位于 `F:` 盘时，Java 会把默认路径解析为：

```text
F:\camera-safe-routing-data\
├─ osm\
│  ├─ jingjinji-latest.osm.pbf      当前使用
│  ├─ china-latest.osm.pbf          后续月度源文件，可选保留
│  └─ beijing-latest.osm.pbf        历史北京文件，可选保留
├─ cameras\
│  └─ camera.json                   当前已发布摄像头源快照
├─ boundaries\
│  └─ sixth-ring-boundary.geojson   当前六环内外边界，包含来源 PBF 哈希和批准状态
├─ graph-cache\
│  ├─ jingjinji-compliant-distance-v1\ 当前默认 GraphHopper 缓存
│  └─ jingjinji\                    旧 profile 回退缓存，可选保留
├─ snapshots\                       路由禁行边持久化快照
├─ downloads\cameras\               摄像头更新候选文件
├─ work\cameras\failed\             更新失败的隔离文件
├─ backups\cameras\                 摄像头旧版本备份
└─ logs\
   ├─ camera-safe-routing-server.log 当前服务日志
   └─ archive\                       压缩后的滚动日志
```

初始化脚本：

```powershell
Set-Location <仓库的code目录>
.\scripts\init-data-directory.ps1
```

指定其他根目录：

```powershell
.\scripts\init-data-directory.ps1 -DataRoot 'D:\routing-data'
```

脚本只创建目录，不下载、移动或覆盖数据。

## 3. 后端路径解析

`server/src/main/resources/application.yml` 使用以下优先级：

1. 单项环境变量，例如 `ROUTING_PBF_PATH`。
2. `ROUTING_DATA_ROOT` 加标准相对位置。
3. 当前盘根目录的 `camera-safe-routing-data`。

普通开发建议只设置 `ROUTING_DATA_ROOT`。单项覆盖用于容器挂载、只读 PBF 盘和缓存独立高速盘等特殊部署。

| 环境变量 | 默认相对数据根目录 | 说明 |
|---|---|---|
| `ROUTING_DATA_ROOT` | 当前盘 `\camera-safe-routing-data` | 统一数据根目录 |
| `ROUTING_PBF_PATH` | `osm/jingjinji-latest.osm.pbf` | 当前路网输入 |
| `ROUTING_CANDIDATE_GRAPH_CACHE_PATH` | `graph-cache/jingjinji-compliant-distance-v1` | 当前默认合规距离 profile 图缓存 |
| `ROUTING_GRAPH_CACHE_PATH` | `graph-cache/jingjinji` | `CURRENT` 旧 profile 回退缓存 |
| `SIXTH_RING_BOUNDARY_PATH` | `boundaries/sixth-ring-boundary.geojson` | 六环内外边界 GeoJSON |
| `CAMERA_JSON_PATH` | `cameras/camera.json` | 摄像头源 JSON |
| `CAMERA_SNAPSHOT_PATH` | `snapshots` | 禁行边持久化快照 |
| `CAMERA_UPDATE_DOWNLOAD_PATH` | `downloads/cameras` | 远程更新候选目录 |
| `CAMERA_UPDATE_FAILED_PATH` | `work/cameras/failed` | 校验或发布失败隔离目录 |
| `CAMERA_UPDATE_BACKUP_PATH` | `backups/cameras` | 正式摄像头源旧版本目录 |
| `APP_LOG_FILE` | `logs/camera-safe-routing-server.log` | 当前服务日志文件 |
| `APP_LOG_ARCHIVE_PATTERN` | `logs/archive/camera-safe-routing-server.%d{yyyy-MM-dd}.%i.log.gz` | 滚动归档文件名模式 |

`server/.env.example` 是变量清单，不会被 Spring Boot 自动加载。IDEA 中应把变量放到 Run Configuration 的 Environment variables；PowerShell 中应在启动 Maven/JAR 的同一进程设置；部署时由服务管理器、容器或系统环境提供。

Linux 服务器不建议直接使用默认 `/camera-safe-routing-data`，除非部署用户确实有该目录权限。推荐明确设置：

```text
ROUTING_DATA_ROOT=/srv/camera-safe-routing-data
```

## 5. PBF 命名规则

当前和后续文件统一使用小写区域名加 `-latest.osm.pbf`：

| 文件 | 用途 |
|---|---|
| `beijing-latest.osm.pbf` | 历史北京路网，可选保留，不再作为默认输入 |
| `china-latest.osm.pbf` | 中国月度下载源 |
| `jingjinji-latest.osm.pbf` | 当前京津冀路网 |

`latest` 文件表示当前已发布版本，不承担历史追溯。归档文件使用日期和哈希，例如：

```text
beijing-2026-07-29-4def579524c3.osm.pbf
jingjinji-2026-08-01-a1b2c3d4e5f6.osm.pbf
```

下载中的文件必须使用 `.part` 或放在 `downloads`，通过完整性、范围和路线回归后才能原子发布为 `latest`。

## 6. 图缓存生命周期

GraphHopper 缓存与以下内容绑定：

- PBF SHA-256。
- GraphHopper 版本。
- encoded values 和 profile。
- 图构建方式。

缓存目录中的 `camera-safe-source.sha256` 记录 PBF 哈希，`camera-safe-routing-config.sha256` 记录 GraphHopper 版本、encoded values、profile、turn costs 和权重规则指纹。若 PBF 或路由配置与缓存不一致，服务会拒绝启动，而不是静默混用旧 edge ID。候选模式还会拒绝缺失路由配置元数据的历史目录。

更新 PBF 时必须：

1. 停止或保持旧服务继续使用旧目录。
2. 在新的空缓存目录构建图。
3. 重建摄像头禁行边快照。
4. 运行真实匹配、零冲突路线和缓存加载回归。
5. 切换配置并重启。
6. 保留上一版本直到新服务验证通过。

不要把多个地区或多个 PBF 版本写入同一缓存目录。

## 7. 摄像头和快照

`cameras/camera.json` 是当前发布输入。更新前的旧版本进入 `backups/cameras`，校验失败的候选进入 `work/cameras/failed`。快照文件由后端生成，包含摄像头源哈希、图指纹、安全半径、匹配数、未匹配 ID 和禁行 edge ID。

快照不能跨 PBF 缓存复用。图重建后 edge ID 会变化，必须重新匹配。

生产加载器只排除 `IsSixRingOut` 字符串或数值语义为 `1` 的记录；缺失和非法值保留并计数。后续更新任务和加载器都应执行该规则，形成双重防护。

后端启动时只根据现有 `camera.json` 重建快照，不等待远程下载。定时更新和本机 `/api/v1/admin/camera-data/update` 接口共用候选校验、备份、原子切换和防重入逻辑。相同内容的禁行边快照不会重复写入，旧源、快照和失败候选都会按数量上限清理。

## 8. 日志目录和保留策略

后端日志同时输出到启动控制台和 `logs/camera-safe-routing-server.log`。项目业务日志使用中文；Spring Boot、Tomcat 和 GraphHopper 等依赖框架自身的日志可能仍为英文。

日志跨天或当前文件达到 50MB 时滚动到 `logs/archive` 并使用 gzip 压缩。默认最多保留 30 天且归档总量不超过 2GB，任一限制触发都会删除最旧归档；当前正在写入的日志文件不计入归档数量。服务启动时也会执行一次历史清理。

Windows 实时查看默认数据目录日志：

```powershell
Get-Content 'E:\camera-safe-routing-data\logs\camera-safe-routing-server.log' -Tail 100 -Wait
```

如果设置了 `ROUTING_DATA_ROOT` 或 `APP_LOG_FILE`，应改用对应路径。日志不得包含 Cookie、令牌、密钥或完整用户定位。

## 9. 前端环境变量

Vite 会自动读取 `web/.env.local`，该文件已被 Git 忽略。

| 变量 | 本地联调建议 | 说明 |
|---|---|---|
| `VITE_AMAP_KEY` | 用户填写 | 高德 Web JS Key |
| `VITE_AMAP_SECURITY_CODE` | 用户填写 | 高德安全密钥 |
| `VITE_API_BASE_URL` | 留空 | 使用 Vite `/api` 代理到 8080 |
| `VITE_USE_MOCK_API` | `false` | `true` 时完全使用前端 mock |

修改 `.env.local` 后必须重启 Vite。真实 Key、密钥和本地 HTTPS 证书不得提交到 Git。

## 10. 新电脑接入清单

1. 克隆 `code` 仓库。
2. 安装 JDK 21、Maven 3.8+ 和 Node 24.16.x。
3. 运行数据目录初始化脚本。
4. 将已切分并验证的 `jingjinji-latest.osm.pbf` 放到 `osm`。
5. 获取当前 `camera.json` 到 `cameras`。
6. 获取与当前 PBF 哈希匹配的 `sixth-ring-boundary.geojson` 到 `boundaries`。
7. 在 `web/.env.local` 填写高德配置。
8. 后端首次启动生成缓存、六环通行口拓扑和摄像头快照。
9. 检查 readiness，再启动前端真实联调。
10. 运行验证指南中的默认测试和至少一个真实数据测试。

整个流程不需要写死仓库绝对路径。
