# 验证与测试指南

## 1. 验证层级

| 层级 | 目的 | 是否需要真实外部服务 |
|---|---|---|
| 单元/组件测试 | 业务分支、协议、坐标和 UI 状态 | 否 |
| 真实文件测试 | PBF 导图、摄像头匹配、缓存和零冲突路线 | 需要本地 PBF/JSON，不访问远程接口 |
| HTTP 联调 | 前后端契约、状态码和手动重算 | 需要本地后端 |
| 高德/桌面联调 | 地图、搜索和渲染 | 需要高德 Key 和网络 |
| 手机 HTTPS | 定位权限、响应式和局域网 | 需要可信证书和真机 |

验证结果必须注明所处层级。mock 通过不等于真实高德或真机通过。

## 2. 准备数据路径

从 `code` 目录执行：

```powershell

$routingDataRoot = Join-Path $driveRoot 'camera-safe-routing-data'

Get-FileHash -Algorithm SHA256 -LiteralPath $pbf, $cameraJson
```

候选边界和 V2 缓存默认放在 workspace；验证命令不得覆盖运行数据根中的现有边界或缓存。生产批准后可把这两个变量改为运行目录的已发布路径执行同一套回归。

### 6.1 朱辛庄到武清专项验收

在真实高德搜索中选择 `朱辛庄新区南区` 为起点、`武清区龙意园` 为终点并请求路线，验收以下结果：

- `planningMode = CROSS_BOUNDARY_OUTBOUND`，`boundaryCrossing`、`safeSegment` 和 `referenceSegment` 均非空；两个 handoff 必须同时非空或同时为空。
- `boundaryCrossing` 只作技术审计，出界取最终路线最早一次有效出界；handoff 非空时，`navigationHandoff` 必须严格位于并集边界外的普通道路，且与 `externalHandoff` 坐标一致。
- `safeSegment` 末点、`referenceSegment` 起点和 `navigationHandoff` 必须 0 米连续拼接。
- 路线进入释放阶段后可以使用六环主路、六环外通州高速主路和其他界外道路；高速主路可以在几何上重新进入受控区，但不得下高速或转入受控普通道路，六环内其他高速主路不得使用。
- 不得复现“小汤山西桥出界 -> 返回受控区域 -> 东侧再次出界”。
- 完整 `geometry` 仍满足 `cameraConflictCount = 0`；该值表示适用摄像头规则的非高速主路冲突为零，并通过独立 trace/JTS 终检。
- 地图保留完整路线并只标记 `navigationHandoff`；切换受控侧行程后只显示界内端点至导航交接点。弹窗地标必须围绕 `navigationHandoff` 按后端动态半径解析，优先收费站、高速出入口和互通；复制的是可搜索地标描述，高德导航链接则使用精确 GCJ-02 坐标。

本机没有当前真实 PBF、边界和摄像头文件时必须把该项记录为“未执行”，不得用 Mock 或旧四方向报告代替。

历史基线：2026-08-06 曾使用 `COMPLIANT_DISTANCE_V1` 和旧六环边界完成专项验证，只用于回归对照。当前 V2.2 回归必须记录释放点、`Dmin`、受控侧距离、距离层、完整时间、动态交接半径和接口耗时。

反向 `武清区龙意园 -> 朱辛庄新区南区` 还必须验收：

- `planningMode = CROSS_BOUNDARY_INBOUND`，完整距离在固定夹具的 100 至 230 公里范围内；`boundaryCrossing` 取实际行驶方向最后一次有效入界。
- 普通道路点不可用时允许返回 `type = HIGHWAY`，但必须位于最终路线的高速主路、严格界外且距物理边界交点沿路线不超过 500 米；匝道、隧道和轮渡不可作为交接点。
- `safeSegment` 起点和 `referenceSegment` 终点均等于交接点；`externalHandoff` 与 `navigationHandoff` 使用同一坐标。
- `HIGHWAY` 固定返回 `poiSearchRadiusMeters = 0`，前端不得替换成附近收费站、酒店或其他 POI，直接使用精确 GCJ-02 坐标导航。

历史基线中的反向坐标和距离来自旧边界，仅用于帮助人工比较；新并集边界可能选择不同通行口和交接点，不得把旧坐标写成当前预期值。

## 8. 后端启动与 HTTP 冒烟

建议 VM options：

```text
-Xms1g -Xmx2g
```

PowerShell 启动：

```powershell
mvn spring-boot:run
```

首次启动导图时 `/health` 可以成功而 `/readiness` 暂时返回 503。就绪后：

```powershell
Invoke-RestMethod http://localhost:8080/api/v1/health
curl.exe -i http://localhost:8080/api/v1/readiness
Invoke-RestMethod http://localhost:8080/api/v1/camera-snapshots/current
```

固定路线请求：

```powershell
$body = @{
  start = @{
    lng = 116.3975
    lat = 39.9087
    coordinateSystem = 'WGS84'
    source = 'CURRENT_LOCATION'
  }
  end = @{
    lng = 116.4700
    lat = 39.9920
    coordinateSystem = 'WGS84'
    source = 'MAP_PICK'
  }
  vehicle = 'CAR'
} | ConvertTo-Json -Depth 4

$route = Invoke-RestMethod `
  -Method Post `
  -Uri 'http://localhost:8080/api/v1/routes' `
  -ContentType 'application/json; charset=utf-8' `
  -Body $body

if ($route.cameraConflictCount -ne 0) {
  throw "Unsafe route: cameraConflictCount=$($route.cameraConflictCount)"
}
$route | Select-Object routeId,distanceMeters,durationSeconds,cameraConflictCount
```

还应验证：起点限制、终点限制、超出路网、服务未就绪和无合规路线均返回 OpenAPI 定义的错误体。

## 9. 摄像头刷新验证

刷新仅允许本机调用：

```powershell
$before = Invoke-RestMethod http://localhost:8080/api/v1/camera-snapshots/current
$accepted = Invoke-RestMethod `
```

验证刷新期间旧快照仍可用，成功后版本变化，失败时版本不变化。不要通过修改原始 JSON 制造失败，使用测试夹具或候选副本。

远程数据立即更新也只允许本机调用：

```powershell
$result = Invoke-RestMethod `
  -Method Post `
  http://localhost:8080/api/v1/admin/camera-data/update
$result | Format-List
```

响应为 `UPDATED` 时检查 `sourceRecordCount`、`retainedRecordCount`、`excludedRecordCount`、匹配数和哈希；远程内容与当前文件相同时返回 `NO_CHANGE`。验证 `backups/cameras` 中存在旧 `camera.json`，正式文件和当前快照哈希一致，超过配置上限的旧文件已清理。该调用会访问真实远程接口，默认测试套件不会执行。

内部定时任务默认关闭。测试部署可设置以下变量并重启后端，无需配置操作系统定时任务：

## 12. 手机 HTTPS 和定位

浏览器 Geolocation 在手机局域网地址上通常要求可信 HTTPS。项目不会提交开发私钥；每台开发机单独生成。

Windows 推荐通过 winget 安装 mkcert：

```powershell
winget install FiloSottile.mkcert
```

winget 不可用时，可从 [mkcert 官方发行版](https://github.com/FiloSottile/mkcert/releases) 安装并加入 PATH。安装后重新打开 PowerShell。先运行 `ipconfig` 确认本机局域网 IPv4，再执行：

```powershell
Set-Location .\web
New-Item -ItemType Directory -Path .\certs -Force | Out-Null
mkcert -install
mkcert `
  -cert-file .\certs\dev-cert.pem `
  -key-file .\certs\dev-key.pem `
  localhost 127.0.0.1 ::1 <本机局域网IP>
npm run dev:https
```

手机需要信任对应开发根证书，并访问 `https://<本机局域网IP>:5173`。通过以下命令查看本机开发 CA 目录：

```powershell
mkcert -CAROOT
```

只将该目录中的 `rootCA.pem` 安装到自己的测试手机，不得复制或分享 `rootCA-key.pem`。Android 在系统安全设置中安装 CA 证书；iOS 安装描述文件后，还需在“设置 -> 通用 -> 关于本机 -> 证书信任设置”中启用完全信任。

同时检查：

- 手机与电脑在同一局域网。
- Windows 防火墙允许 Node/Vite 端口。
- 高德控制台允许当前开发来源。
- 浏览器站点位置权限为允许，而不是系统允许但站点阻止。
- 地址栏没有证书警告；有警告时 Geolocation 仍可能被拒绝。
- 证书包含当前局域网 IP；电脑 IP 变化后应重新生成证书。

真机至少验证竖屏、横屏、软键盘、定位精度圆、拖图不自动回中、回到当前位置、手动重新规划、出入环点弹窗不被面板遮挡，“复制地标”得到的是可以直接粘贴到移动端高德搜索的位置描述，以及“高德导航”能按正确方向打开精确坐标路线。

## 13. 性能验证

后端启动后：

```powershell
.\scripts\benchmark.ps1 -Iterations 50 -Warmup 5
```

记录首次导图、缓存加载、图缓存大小、路线 P50/P95、最慢无路请求和 JVM 堆。扩大到京津冀后必须重新测量，不能沿用北京数据指标。

跨界性能回归必须包含冷启动首请求，并至少覆盖 `朱辛庄新区南区 -> 武清区龙意园`。边界遍历约束应使用预处理几何和基础 edge 缓存；测试还要确认 `QueryGraph` 虚拟 edge 不会因临时 ID 复用而读取其他吸附点的缓存结果。

前端在真实手机检查摄像头图层、路线折线、定位更新和底部面板是否卡顿。不要为每个摄像头创建一个 Vue 组件实例。
